
## 0. 定位与边界

### 0.1 目标

角色行动之后，要把互动结果变成能影响未来的持久变化。这个变化有快有慢：情绪很快恢复，关系和记忆跨事件保留，信念、自我评价和策略在多次经历中积累，角色的长期目标、身份和发展取向只在重复或重大的证据下缓慢调整。本 skill 要分开回答五个问题：这次结果在角色看来是什么，它属于哪一层的变化，哪些状态因此改变、改变多少，哪些状态应当保持不变，是否已经积累到值得提出长期基线修订的程度。

### 0.2 负责范围

本 skill 覆盖从行动反馈到持久状态的全过程。它先对照计划时的预期和角色理解到的实际结果，判断变化属于哪一层、需要多强的证据；再做面向学习的结果归因，巩固事件记忆，认定承诺的兑现、延误或违约，处理关系、伤害与修复，更新声誉、群体位置、信念、自我评价、策略权重和当前目标，并在无新证据时按各字段的时间规则处理衰减与恢复。最后检查长期适应门槛：达到门槛时生成 stable 修订候选，未达到时只更新 dynamic 和 memory。过程中产生的持久变化，以候选状态变化的形式提交。

### 0.3 不负责范围

本 skill 不解释新到达的反馈，对方的回复、第三方转述和结果核实先由 事件建模skill解释，本 skill 读取解释后的结果。它不选择下一步行动；它可以决定关系走向和修复条件，但具体怎么说、怎么做由行动计划skill生成。它不直接写 stable，长期基线的变化只以修订候选形式提出，审核和版本迁移不在轨迹运行中完成。

### 0.4 与前后 skill 的接口

上游输入有两部分。来自事件建模skill的，是此前交出的关系信号、承诺信号和伤害线索，以及反馈阶段的情境解释，后者说明角色怎样理解反馈。来自行动计划skill的，是选定行动、预期结果、观察指标、所形成的承诺和计划所依赖的假设。两部分里的推断和预期都是候选，本 skill 只依据角色实际经历和理解到的结果更新状态。

下游方面，本 skill 提交的状态版本供下一阶段和下一事件读取。事件建模用更新后的关系史和记忆作为解释背景，行动计划用更新后的策略权重、承诺状态、当前目标和修复条件作为规划起点。stable 修订候选交给心理学组审核，生效之前，后续事件仍读取原 stable。

## 1. 触发条件

### 1.1 结果与承诺触发

行动反馈到达并已由事件建模解释后，触发本 skill。具体包括：承诺被形成、兑现、暂停、延误、违约或撤销；出现伤害、道歉、解释、补偿、边界侵犯或重复失信；重要目标达成或长期受阻；行动明显成功或失败；他人或群体给出评价、认可或排斥。承诺的认定不限于他人：角色自己作出的承诺是否完成，也在这里认定。

### 1.2 结构与模式触发

下列变化也会触发本 skill：角色转换、资源条件改变、制度变化、身份受到威胁；同一类互动模式在多个事件中重复出现；角色在事件中或事后明确进行自我重评、调整长期计划。这类触发往往需要读取较长的历史，才能判断它是一次偶然还是一种模式。

### 1.3 时间触发

纯粹的时间推进、没有新线索时，本 skill 只运行衰减与恢复部分。恢复窗口到期、修复观察期结束、承诺期限到达，也属于时间触发；期限到达而角色没有看到兑现的证据时，承诺状态的认定要等事件建模先把“未见到兑现”确认为角色可见的事实。

### 1.4 不触发的情形

角色没有经历、没有被告知、也无从推知的结果，不触发本 skill，即使系统已经知道真实结果。只有意图而没有行动、只有预测而没有反馈时，不提交任何持久变化。

## 2. 输入与读取来源

### 2.1 结果、反馈与上游交接

核心输入是角色理解到的结果：事件建模在反馈阶段给出的事实确认、归因、他心假设的修订和判断状态。行动计划的预期结果和观察指标，是判断“结果是否如预期”的对照。事件建模此前交出的关系信号和承诺信号，连同它们所依赖的假设一起读入；这些假设在反馈后若已被取代，依赖它们的信号要相应降权或撤回。

评估结果的重要性时，还要读入事件的严重度、重复性、可控性、责任与意图、结果能否被验证、外部结构是否改变，以及角色能把结果归因于自己、他人还是情境。系统掌握的真实结果不进入这一输入。

### 2.2 stable

identity 中的社会角色、制度位置和资源条件，决定一次结果对角色的分量，例如同样的失败对承担正式责任的人影响更大；资源和角色位置的变化本身也是长期适应的证据来源。角色认同中的身份标准、显著性和承诺，决定哪些反馈构成身份验证、哪些构成不验证。

traits 中，成人依恋影响角色对伤害和修复的敏感性、对回应延迟的耐受，以及求助未被回应后的反应（决策 8.6）。动力基线和人格影响学习速度和恢复速度，不直接决定变化方向。发展位置决定角色以什么方式组织经验的意义，它本身在普通轨迹内固定。自我系统提供自尊的水平、稳定性和条件性，自我差异的标准和来源，以及认同状态。防御成熟度决定角色面对自我威胁的结果时，是先防御、事后整合，还是长期扭曲责任。

values 和 core_goals 用来判断结果触及了哪些长期优先事项，也是长期适应门槛的比较对象。它们在本 skill 中被读取和比较，不被普通状态变化改写。

### 2.3 dynamic

relation_state 是本 skill 的主要写入对象之一：信任、亲近、依赖、承诺四项分别读取，伤害历史按条目读取，权力差作为关系背景。

policy_state 提供当前策略、备选方案、切换条件、反馈权重、学习历史和未完成承诺。

goal_state 提供当前目标、承诺度和可行性，以及它们与核心目标的链接。

cognition_state 提供已有信念、对他人的推断、归因和自我评价。

group_state 提供成员资格、身份显著性、规范显著性、联盟和责任分配。

affect_state 提供当前情绪和唤醒，用于衰减与恢复，也用于判断角色此刻是否在反刍。

### 2.4 memory、thought 与 mechanism_log

memory 提供相关的事件记忆、承诺履行记录、伤害与修复历史、峰值事件和相似情境，用于判断这次结果是孤立事件还是重复模式。mechanism_log 提供此前各阶段的完整理由链：当时的证据、假设、候选行动、未选原因、预期和切换条件，用来对照结果，并保证更新有可追溯的来源。thought 是模型的原始输出，不作为证据。

### 2.5 读取快照与优先级

本 skill 读取事件建模在反馈阶段提交之后的快照，同一角色、同一事件、同一阶段只读这一份；行动计划在同一反馈上的修订，读取本 skill 提交之后的快照。内部各步骤之间传递的判断都是候选，不是已生效的状态。

证据方面，角色直接经历的结果优先于他人转述，可验证的行动优先于口头表态。涉及特定对象时，对象特异的关系史优先于全局依恋基线。某个模块处于未知、关闭或未建模状态时，跳过依赖它的更新，记为信息不足，不用默认值冒充观测；没有时间规则的字段不默认衰减。

## 3. 处理流程

### 3.1 对照预期与实际结果

先把行动计划的预期结果、观察指标与角色理解到的实际结果逐项对照：哪些如预期，哪些偏离，偏离的方向和程度如何。结果要分维度记录，任务可能成功而关系受损，也可能短期失败而建立了信任，不压成成功或失败的二元标签。

这里只使用角色经历和理解到的结果。角色还没有看到的后果，留待之后的阶段；系统知道的真实结果不能替代角色自己的认知。

### 3.2 判定变化层级与时间尺度

判断这次结果涉及哪一层的变化，并确定每层需要的证据强度。事件层包括情绪、注意、威胁或奖赏激活和当下目标，单次事件即可触发，变化快，可衰减或恢复。关系与记忆层包括信任、亲近、依赖、承诺、伤害历史、声誉和事件记忆，由有关系意义的行为、违约、修复和重复互动触发，跨事件持续，受后续证据影响。策略与自我层包括信念、自我效能、责任感、策略权重、切换阈值和对他人的预期，由结果反馈、成功或失败的模式、他人评价和策略反复失效触发，在中期积累，可迁移到相似情境。角色基线层包括核心目标、角色身份与角色承诺、价值显著性、长期发展取向，以及部分能力或人格表现基线，只有重复且一致的证据、重大转折、角色转换、长期资源和制度变化或明确的自我重评才可能触发，变化慢而稀疏，只能以修订候选形式提出。

同一结果可以同时产生不同层级的变化。例如一次公开违约，既可能降低对违约者的信任，写入伤害记忆，改变合作策略，也可能在长期重复后改变角色对“他人是否可靠”的一般信念。这些变化分层记录。

### 3.3 面向学习的结果归因

事件建模已经对反馈事件本身做了归因，本 skill 在此基础上回答学习所需的问题：结果在多大程度上来自角色自己的策略，多大程度上来自对方，多大程度上来自情境或偶然。只有能归于自身策略的部分，才进入策略学习；归于对方的部分，进入关系和对他人的预期；归于情境的部分，进入对环境的信念。

要区分“发生了一个坏结果”和“我因此形成了什么一般化信念”。一次结果可以只留在事件记忆里，不推广成规则。对自己和对他人的归因仍分开记录，自利偏差之类的不对称要能由角色的自尊稳定性、防御方式或关系史解释。

### 3.4 巩固事件记忆

把对未来判断或行为有影响的经历写入记忆：发生了什么，谁负什么责任，这件事对角色意味着什么，角色对这一理解的确信程度，以及还有什么没有解决。记忆要保留来源、时间、可见性和重要性。峰值事件、未完成的修复和反复出现的模式，可及性更高；无关紧要的细节不必转成记忆。

记忆不是录像。角色记住的是自己理解到的版本，之后可以被再激活、被新证据重新解释，但原始条目和后来的解释要分开保留，不覆盖历史。

### 3.5 认定承诺状态

对相关的每项承诺，认定它处于兑现、按期进行、延误、重新协商、暂停、违约还是撤销。认定依据承诺本身写明的内容、期限和验证条件，以及角色可见的履行证据。迟于期限但最终完成、事前预警后调整范围、未作说明的失约，是三种不同的状态，要分别记录。

承诺认定之后，再看它对其他状态的影响：违约是否构成伤害，兑现是否构成可靠性证据，重新协商是否改变了关系中的期待。公开承诺的违约对声誉的影响通常大于私下承诺。角色自己的承诺同样要认定：按期完成会支持当前任务的自我效能，失约则带来责任评价和面子上的压力，角色可能承认、解释、补救，也可能隐瞒或转移责任，这些反应要能从角色设定中解释。

### 3.6 关系、伤害与修复

关系的四个维度分别更新：信任主要由可靠性证据更新，亲近由情感互动和边界事件更新，依赖由资源、照料和替代选项的变化更新，承诺由关系义务的形成、兑现和违约更新。同一事件可以影响多个维度，但各维度的变化分别判断，不按同一比例联动。信任内部还要区分能力、善意、诚信和可靠性：按时完成主要支持能力和可靠性，不自动证明善意；一次自利行为也不必抹去长期的能力记录。

出现伤害时，写入伤害历史，记录严重度、对方是否承认、是否修复和最近一次激活。之后评估修复：伤害的严重度和重复性，对方的责任承认、意图证据、解释质量、补偿和行为改变，以及角色的关系价值、替代关系和安全。道歉只有在承认具体影响、避免转移责任并有后续行动时才有修复作用；单纯解释原因可能被体验为辩护。

在此基础上，确定关系走向：恢复信任、进入观察期、有条件修复、暂缓信任、维持低强度关系、暂时距离或退出。宽恕可以是立即的、有条件的、观察后的，也可以不发生；宽恕不等于忘记、不等于恢复亲密，也不能被强制生成；和解需要责任承认、行为改变和双方意愿。依恋焦虑高的角色在修复期可能需要更多确认，回避高的角色可能压低需要或先行拉开距离。

关系走向确定后，写明修复条件和验证条件：对方做到什么、持续多久，角色才会进一步恢复信任。具体怎样表达接受、拒绝或提出条件，交给行动计划skill。

### 3.7 声誉、群体位置与规范学习

声誉分两面：角色对他人公共记录的判断，以及角色认为自己在群体中的公共记录。公开承诺、可验证行动和第三方评价改变声誉；传闻、选择性传播和群体偏见也会改变角色对声誉的判断。声誉与个人信任分开保存，群体评价不能自动覆盖角色的直接经验。

群体方面，更新成员资格的显著性、规范显著性、联盟和责任分配。角色受到群体认可、排斥或惩罚后，要判断这对自己的成员资格意味着什么，是否改变自己在群体中的位置。角色此前发起的制裁，要检查停止条件是否已经达到，达到后可以恢复合作；没有停止条件的报复容易升级，这一风险要记录。

规范学习把观察到的“人们实际怎么做”和“人们认为应该怎么做”，转化为内化、表面遵从或抵抗。新成员、角色转换、制度变化和重复互动提高规范更新的速度，高权威依赖、身份威胁和封闭群体可能降低它。

### 3.8 信念与自我评价

结果可以修订角色对世界、他人和自己的信念。对特定对象的预期先在对象层面更新，需要跨对象、跨情境的重复证据，才推广为一般信念，例如从“他这次没有提前说明”到“同事遇到问题通常不会提前说”。更新可以发生在个人层、群体层，或者两层都不发生。

自我评价方面，更新当前任务的自我效能、责任评价、羞耻和面子成本。社会比较会影响这一过程：角色与谁比较、比较方向如何、是否校正了资源和机会的差异，决定比较结果是促成学习还是带来自责或优越感。动态自我状态的变化不改写动力系统中的稳定自我效能基线。

对外部反馈，角色可以采纳、部分采纳、质疑、拒绝、反击或转移责任；可以接受内容而拒绝反馈者的权威，也可以因关系安全而采纳低质量建议。面子和身份保护强时，角色可能先防御，等威胁降低后再私下整合。事件引发的反复思考要区分问题分析和情绪反复：前者以产生新信息或方案为终点，后者没有新的行动，只增加对睡眠、关系和任务的代价。

### 3.9 策略学习

比较策略的预期结果和实际结果，结果比预期好，提高这一策略在相似情境下的权重，比预期差则降低。学习不等于服从最后一次反馈：角色会按来源可信度、结果的偶然性、关系价值和可控性折扣反馈；只有在 3.3 中归于自身策略的部分才参与学习；羞辱性的反馈可能触发防御而不是学习。

观察他人的成功和失败，也会改变角色的策略，替代性的奖惩与直接经历的结果分开记录。策略反复奏效会逐渐形成习惯，习惯被打断后，要记录恢复、替代、压制还是重新固化。切换阈值同样可以学习，例如对某个对象的观察期变长或变短。学习的对象要区分：行为脚本、行动价值、规范可信度、对反馈的信任和习惯强度，不是同一个变量。

### 3.10 当前目标的重排

依据结果，把当前目标标为完成、继续、受阻、降级、暂停或替换，更新它们的可行性和优先级，并保留与核心目标的链接。下位手段失败时，可以换手段而保留上位目标；重要目标长期受阻时，先降低可行性和激活，而不是改写核心目标。核心目标的任何改变，只能经 3.12 的修订候选提出。

### 3.11 衰减与恢复

没有新证据时，各状态按字段自身的时间规则衰减或恢复：情绪回落，威胁激活消退，伤害的显著性随时间降低，策略权重缓慢恢复。没有规则的字段不默认衰减，不能把信任、伤害、策略和目标都自动拉回初始值。人格影响的是恢复速度，不是变化方向。

恢复不是简单的遗忘。它可以包括唤醒下降、获得安全、重新解释、完成未竟的行动、修复关系、恢复日常节律和把事件纳入自我叙事。旧事件遇到相似线索时可以被再激活，伤害显著性回升，这要记录再激活的线索。

### 3.12 长期适应门槛与 stable 修订候选

只有明确设计为长期发展轨迹时，才检查长期适应门槛；单条普通评测轨迹内，stable 默认固定。门槛有四个：证据门槛，单次普通事件通常不足，需要重复的模式、重大转折或明确的长期反馈；一致性门槛，变化要在多个相关事件、关系或角色情境中得到支持，或有足够强的单次事件理由；心理整合门槛，角色能够把变化纳入自己的信念、身份、目标或长期计划，而不是系统事后替它改字段；范围门槛，变化先局部生效，从某段关系、某项策略或某个子目标扩展到一般性的核心目标或身份，需要额外证据。同时检查替代解释：同一现象能否由当前压力、关系特异的经历或资源暂时变化解释。

不同 stable 内容的证据要求各有特点。发展位置需要跨事件或具有生命史连续性的证据，一次成熟表达或一次冲动行为都不足以改变它。认同状态可以因重大转折重新进入探索。价值优先级的变化要与价值在单次事件中的激活区分开，一次强烈反应不是价值重排。

达到门槛时，生成 stable 修订候选，写明变更前后、触发证据、变更理由、有效范围、置信度、可逆性和影响范围。候选可以提议新增、删除、降级或重新排序核心目标，也可以提议调整角色身份、价值优先级或发展取向。核心目标的修订候选由 `goal_update` 记录；其他 stable 字段的修订候选同样以修订提案形式提交审核，不经普通状态变化写回。候选经心理学组审核和兼容校验后，通过版本迁移生成新的 stable 快照，旧快照和重新评测要求一并保留。

候选生效前，后续事件仍读取原 stable。长期经历在本轨迹内的影响，只能通过 dynamic 体现：goal_state 中的目标激活、动态承诺和可行性，cognition_state 中的信念和自我评价，policy_state 中的策略权重，以及 group_state 中的身份显著性。未达到门槛时，只更新这些动态状态和记忆。

### 3.13 面向未来的计划与传播

最后整理交给后续阶段的内容：新的子目标、修复与验证条件、备用策略、恢复路径，以及下一次应观察的证据。长期变化通过已提交的状态传播到后续决策，但同一事件内不级联：本阶段提交的变化，只在下一阶段被读取，不在本阶段内触发新一轮更新。

## 4. 调用机制与更新算子

### 4.1 决策机制

本 skill 调用的机制来自决策机制库的七个部分。信息加工部分提供归因与责任判断（1.8），在本 skill 中用于面向学习的结果归因。评价与调节部分提供防御机制（2.5），以及反刍、恢复与自我控制（2.6）。社会交互部分提供印象形成与刻板化（3.3）中的反例整合、信任与声誉更新（3.4）和社会比较与自我评价（3.5）。学习部分提供社会学习与模仿（4.1）、强化与目标导向学习（4.2）、规范与文化学习（4.4）、反馈接受与适应速度（4.5）和习惯与目标导向行动（4.6）。合作部分提供信任建立与撤回（7.3）、互惠与制裁（7.4）和信号、承诺与声誉（7.6）。冲突部分提供关系修复与退出（8.5）和依恋激活与支持交换（8.6）。社会结构与亲社会部分提供群体边界与身份切换（9.8）、规范执行与社会惩罚（9.13）、责任承担与转移（10.2）和宽恕、和解与记忆保持（10.3）。

机制组合遵循各章的组合规则：学习各模块的更新对象分开，长期轨迹允许策略权重慢速改变，普通单次事件只改变状态和有限历史；合作各模块分别保存状态，不用一个合作分数代替；冲突后的长期更新区分情绪恢复、信任恢复、规则改变和关系结构改变；基线固定、事件后可更新和长轨迹变化三类内容分开处理。所有机制只产生中间判断、候选变化和未选原因，没有状态写权限。

### 4.2 更新算子

本 skill 调用九个更新算子。`memory_update` 写入事件记忆的形成、巩固、再激活和可及性变化。`commitment_update` 写入承诺的兑现、延误、重新协商、暂停、违约和撤销，以及修复条件。`relation_update` 写入信任、亲近、依赖、承诺和伤害历史等已上线的关系字段；修复和声誉的结果也经它写入已上线的字段，算子存在不代表所有候选字段都已上线。`belief_revision` 写入关于世界、他人和自己的信念修订，包括从对象层推广而来的一般信念。`self_state_update` 写入当前任务自我效能、责任评价、羞耻和面子成本的变化。`group_state_update` 写入成员资格显著性、规范显著性、联盟、群体边界和责任分配的变化。`goal_update` 写入当前目标的完成、受阻、降级、暂停或替换，以及核心目标的修订候选。`strategy_learning` 写入策略权重、切换阈值和学习历史。`decay_or_recovery` 按字段的时间规则处理情绪恢复、激活消退、伤害显著性和策略权重的恢复。

本 skill 不调用 `emotion_update` 和 `other_model_update`。角色对反馈的情绪反应和对他人心理的修订，由事件建模在反馈阶段完成；情绪随时间的回落经 `decay_or_recovery` 处理。stable 修订提案不是更新算子，不经普通状态变化，按 3.12 的流程处理。

### 4.3 执行顺序、候选 StateDelta 与提交

逻辑顺序为结果对照、层级判定、结果归因、记忆巩固、承诺认定、关系与修复、声誉与群体、信念与自我评价、策略学习、目标重排、衰减与恢复、长期适应检查。这是保证可复现的计算顺序，不意味着心理过程是线性流水线。

所有候选变化都以同一份快照为前提。来自同一证据的承诺认定、伤害记录和关系变化相互依赖，放在同一依赖组内提交；同一路径上，同一证据的多次贡献先去重，不能重复计入。变化幅度要与事件严重度、证据强度、重复性和角色敏感度相称；人格的作用落在敏感度、峰值、持续时间或恢复速度上，不直接放大变化量。重大跃迁必须有明确的触发、证据和角色可以理解的心理路径。

### 4.4 mechanism_log 记录

日志要让每一项持久变化都能回溯到具体的经历。它应记录：预期与实际结果的逐项对照；变化层级的判断及所需证据强度；面向学习的归因，以及哪些部分进入策略学习、哪些进入关系或环境信念；承诺认定的依据；关系各维度分别变化的理由，修复评估和关系走向；信念是停留在对象层还是推广为一般信念；反馈接受方式和是否出现防御；策略权重变化的来源和折扣理由；衰减与恢复所依据的时间规则和再激活线索；长期适应门槛的逐项判断，包括未达到的门槛和替代解释；修订候选的全部内容；以及候选与最终状态变化、被拒绝的项目和异常标记。

## 5. 输出与接口

### 5.1 演化结果

输出一个演化结果，内容包括预期与实际结果的对照、变化层级判断、结果归因、巩固后的事件记忆、承诺状态、关系各维度的变化与关系走向、修复与验证条件、声誉和群体位置的变化、信念与自我评价的变化、策略学习结果、当前目标的重排、衰减与恢复的处理、长期适应门槛的判断，以及是否生成 stable 修订候选。

### 5.2 状态变化候选

候选状态变化覆盖 memory 和六个状态域中除情绪即时反应之外的持久部分。每条候选变化都要引用角色经历的结果和对应的事件记忆，说明调用了哪些决策机制，经哪个更新算子写回，属于哪一变化层级。

### 5.3 stable 修订候选

只有达到长期适应门槛时才生成。修订候选写明变更前后、触发证据、变更理由、有效范围、置信度、可逆性和影响范围，交给心理学组审核。它在审核和版本迁移之前不生效，本轨迹内的影响只通过 dynamic 体现。

### 5.4 交给下一阶段的内容与条件

本 skill 提交后的状态版本，是下一阶段和下一事件的读取起点。事件建模skill用更新后的关系史、伤害历史和事件记忆作为解释背景，用修复和验证条件判断之后的行为是否构成修复证据。行动计划skill用更新后的策略权重、承诺状态、当前目标和关系走向规划下一步，把修复条件和需要表达的关系立场转为具体行动。

尚未解决的问题，例如观察期中的信任、未完成的修复、低确信的一般化信念，连同下一次应观察的证据一起保留，作为本 skill 下一次运行的起点。

## 6. 约束与异常处理

### 6.1 证据与写入边界

结果必须先被角色经历、解释和归因，才能影响关系、策略或基线；系统知道的真实结果不能替代角色自己的认知。普通状态变化不得写 stable；stable 的变化只能以修订候选形式提出。本 skill 不写情绪的即时反应和他人模型。这些都属于硬约束，违反时拒绝所在的整组变化。

### 6.2 关系维度不混同

道歉不等于修复，修复不等于信任完全恢复，宽恕不能被强制生成。关系承诺、具体行动承诺、声誉和伤害历史分开记录；信任的能力、善意、诚信和可靠性分开判断；关系的四个维度不按同一比例联动。

### 6.3 幅度相称与路径依赖

单次事件最多产生与其严重度相称的动态变化。核心目标、稳定价值、人格和角色身份的变化，要慢于当前目标、情绪和策略权重，并且可以始终不变；不能因为一次失败就把核心目标改成相反方向。过去的经历通过记忆和关系史影响新的更新，同一结果对有不同历史的角色可以产生不同变化，这种路径依赖和滞后是正常的，不需要抹平。

### 6.4 无证据不衰减到初始值

无新证据的状态按字段自身的时间规则衰减或恢复。没有规则的字段保持原值，不能默认所有信任、伤害、策略和目标都自动回到初始值。

### 6.5 软异常

以下情况按软异常处理，结果保留并标记待复核：变化幅度落在典型区间之外；衰减过慢或恢复过快；一次普通事件引起明显的跨字段联动；学习结果与归因方向不符，例如把明显来自情境的结果全部计入自身策略，又找不到角色偏差的解释；同一模式重复多次而相关状态始终不变。重大事件可以豁免事先声明允许的软边界，但必须说明依据；硬约束不可豁免。

### 6.6 回放一致性与可追溯

后来的结果不能回头改写早先阶段的解释、理由和预期；新的理解作为新的记忆解释或信念修订保留，旧版本标为已被取代。每项持久变化都要能追溯到具体经历；无法追溯来源的角色变化，以及只能靠临时改写人格或价值才能成立的行为，判为设定漂移。stable 修订保留旧快照、触发证据、变更理由、有效范围、置信度、可逆性和重新评测要求，避免回放时出现无来源的角色漂移。

## 7. 最小示例

### 7.1 输入

接行动计划skill的示例。

周四上午，林晓私下问周凯卡在哪里、下午几点能交、是否需要帮忙协调数据，并给自己定了下班前搭好汇总框架的承诺。周凯中午回复：另一个部门的数据周三晚上才给到，他还在核对，下午四点前发；不需要帮忙，没有提前告知是他疏忽了。下午他按时发来报告，质量没有问题。林晓在下班前完成了汇总框架。

事件建模在反馈阶段已经提交：“报告已交付”和“周凯说明了原因并承认没有提前告知”是事实；林晓无法核实那个部门是否真的延误，她对这一说明的确信度较高，因为它与周凯以往的记录相容；“遇到资源阻碍”的假设得到支持，“排在了别的事情后面”的假设被削弱，二阶假设仍无证据区分。行动计划的预期是私下询问能问清原因，下午能拿到报告，两项都已出现。

### 7.2 处理

对照来看，结果在任务和关系两个维度都与预期一致。变化属于事件层和关系与记忆层，在策略层只有轻微的积累，不涉及角色基线。

归因上，按时拿到报告主要归于周凯和外部数据的到位；能问清原因并保持合作，部分归于林晓先私下询问的做法。只有后一部分进入策略学习。

记忆巩固后的条目是：周凯第二次延期，原因都在外部，两次都在事后说明，都没有提前预警；这次他主动承认了没有提前告知。承诺认定方面，周凯原定周三的承诺记为延误，之后在重新约定的时间兑现，这既不是干净的兑现，也不是违约；林晓自己的框架承诺记为按期兑现。

关系方面，延误没有被林晓体验为伤害，周凯也承认了疏忽，因此不写入伤害历史。信任中的能力和可靠性有一条轻微的负向证据，即没有提前预警，但被说明、承认和按时补交抵消，信任总体维持；亲近、依赖和承诺不变。两次都没有提前预警，形成了一个对象层的弱规律，“周凯遇到外部阻碍时倾向于事后才说明”，以较低确信度写入；它还不足以推广为对同事的一般信念。

策略方面，“先私下询问卡点”在对周凯和类似的交付延迟上权重略有提高。因为结果有一部分取决于外部数据何时到位，学习幅度保持克制。当前目标中，“确认周凯报告的交付时间”标为完成，“周五前提交汇总”的可行性恢复。她对按期完成汇总的把握回升，经 `self_state_update` 写入。上午的轻度烦躁按时间规则回落。

这是普通评测轨迹中的一次普通事件，不检查长期适应门槛，不生成 stable 修订候选。

### 7.3 输出

提交的变化包括：`memory_update` 写入这次延期的事件记忆，并关联两个月前的那一次；`commitment_update` 记录周凯承诺的延误与重新约定后的兑现，以及林晓自身承诺的兑现；`relation_update` 只登记这条可靠性证据及其抵消因素，四个维度不变；`belief_revision` 以较低确信度写入关于周凯预警习惯的对象层规律；`strategy_learning` 小幅提高先私下询问的权重；`goal_update` 关闭已完成的子目标；`self_state_update` 写入自我效能的回升；`decay_or_recovery` 处理烦躁的回落。

交给后续阶段的内容是一个观察点：下次分派依赖外部数据的任务时，周凯是否会提前预警。这条信息供事件建模作为解释背景，也供行动计划考虑是否在分派时先问清上游数据的进度。

另一个组长面对同样的经历，可能得出不同的结果。依恋焦虑较高的组长，可能在周凯说明之后仍保留更多警惕，在下次任务中更频繁地确认进度。这同样合理，只要能从她的依恋取向和关系史中得到解释。

如果这是一条明确设计的长期发展轨迹，林晓在许多项目中反复遇到跨部门数据卡住组员的情况，每次都要在向主管按期交付和保护组员之间取舍，并逐渐把“替团队疏通上游”当作组长职责的一部分来讲述，那么证据、一致性和心理整合三个门槛可能先后满足。这时可以提出修订候选，在“把小组带成能稳定交付的团队”这一核心目标下新增一个支持性子目标，经 `goal_update` 记录，等待审核。审核通过之前，这一变化只体现为她在相关事件中更早激活协调上游的目标，以及相应策略权重的提高。

### 7.4 反例

如果因为系统知道那个部门确实延误了，就把林晓对周凯说明的确信度写成完全确定，属于用系统真实结果替代角色认知。如果把两次延期直接推广为“同事都不可靠”的一般信念，或写入伤害历史并下调信任，属于单次轻度事件下的过度变化。如果在本轨迹中因为这次经历直接改写林晓的核心目标或人格，属于越权写入 stable。如果回头把周四早上保留多个假设的解释改成“当时就确定是资源问题”，属于违反回放一致性。这四种情况都应被拒绝。
