# 角色 Agent ⇄ 场景/环境组 接口合同 v0

## 0. 一句话

环境负责"世界里实际发生了什么、谁看见了"；Agent 负责"这个角色看见之后怎么想、打算怎么做、自己的状态怎么变"。双方只通过两个接口交换数据：`step`（让角色行动）和 `perceive`（让角色感知新事件）。

## 1. 职责边界

| 事项 | 环境组 | Agent 模块 |
|---|---|---|
| 剧本、场景背景、角色出场 | ✔ | |
| 决定本轮谁行动、行动顺序 | ✔ | |
| 角色提出言语/行动 | | ✔ |
| 行动是否成功、产生什么后果 | ✔ 裁决 | |
| 事件最终对谁可见 | ✔ 裁决 | 只提议 |
| 角色心理状态的保存与更新 | 只存快照 | ✔ |
| 角色对他人的推断（可能是错的） | | ✔ |

原则：Agent 给出的是"尝试"，不是"事实"。角色说"我私下告诉 B"，C 有没有听到由环境裁决，再以事件形式回来。

## 2. 数据对象

### 2.1 标识符

- `role_id`：全局唯一字符串，如 `"wang_bo"`【待确认命名规则】
- `turn`：整数，从 1 开始
- `event_id`：环境生成，全局唯一、不复用，建议 `"e{turn:03d}_{seq:02d}"`，如 `"e003_02"`
- `proposal_id`：Agent 生成，如 `"wang_bo@t003#1"`
- `state_id`：Agent 生成，如 `"wang_bo@t003"`；同一轮内多次更新加后缀 `.p1`、`.p2`

### 2.2 Event（环境 → Agent，已裁决的事实）

进入角色视野的一切都是 Event。环境产生，Agent 只读。

```json
{
  "event_id": "e003_02",
  "turn": 3,
  "type": "speech",
  "actor": "li_ayi",
  "target": ["wang_bo"],
  "content": "王伯，加装电梯每户大概要出两百块。",
  "visibility": {"scope": "private", "audience": ["li_ayi", "wang_bo"]},
  "outcome": null,
  "caused_by": "li_ayi@t003#1"
}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `type` | `speech` / `action` / `narration` / `outcome` | `narration` 为旁白或环境变化；`outcome` 为对某次行动的裁决 |
| `actor` | role_id 或 `"env"` | 旁白和裁决填 `"env"` |
| `target` | role_id 列表，可空 | 说话/行动对象 |
| `content` | 字符串 | 该角色能感知到的内容，不是全知描述 |
| `visibility.scope` | `public` / `private` | |
| `visibility.audience` | role_id 列表 | **裁决后**实际能感知的角色 |
| `outcome` | 对象或 null | 仅 `type=outcome`：`{"of_proposal", "status": "success\|partial\|failed\|blocked", "detail"}` |
| `caused_by` | proposal_id / event_id / null | 因果链，用于回放 |

同一件事不同人感知到的内容不同时（例如 C 只听到"隔壁在小声说话"），请拆成多个 Event，各自 audience 不同。

### 2.3 ProposedAction（Agent → 环境，未裁决的尝试）

```json
{
  "proposal_id": "wang_bo@t003#1",
  "kind": "speech",
  "content": "两百块……我得先问问我儿子。",
  "target": ["li_ayi"],
  "proposed_visibility": {"scope": "private", "audience": ["li_ayi"]},
  "intent_note": null
}
```

- `kind`：`speech`（说的话）或 `action`（做的事，如"把通知撕下来"）
- `proposed_visibility`：角色的意图，环境可改写
- `intent_note`：可选，给环境裁决用的简短意图（如"想让对方误以为同意"）。属于私有信息，不得进入任何 Event【待确认是否需要】

**"思考"不是 ProposedAction。** feedback-1015 把思考列为 action 的一种。本合同把它放进单独的 `thought` 字段：固定只有本角色可见，环境只记录，不分发、不裁决。

### 2.4 AgentState（Agent 维护，环境只存不改）

```json
{
  "state_id": "wang_bo@t003",
  "role_id": "wang_bo",
  "turn": 3,
  "prev_state_id": "wang_bo@t002",
  "schema_version": "state-v0",
  "psychology_version": "psy-v0",
  "stable":  {"...": "轨迹内不变，字段由心理学组合同定义"},
  "dynamic": {"...": "可更新，字段由心理学组合同定义"},
  "memory":  ["e001_01", "e003_02"]
}
```

本合同只固定外层结构。`stable`、`dynamic` 的内部字段由心理学组合同定义，环境组可以当不透明 JSON 存。

### 2.5 StateDelta（每次状态变化的审计记录）

```json
{
  "from_state_id": "wang_bo@t002",
  "to_state_id": "wang_bo@t003",
  "trigger": "perceive",
  "changes": [
    {"path": "dynamic.beliefs.elevator_fee", "before": null,
     "after": {"content": "每户约200元", "confidence": 0.6},
     "evidence": ["e003_02"], "mechanism": "belief_revision",
     "reason": "李阿姨私下告知"}
  ]
}
```

硬规则：每条 change 的 `evidence` 只能引用本角色 `memory` 里已有的 event_id，或本角色自己的 proposal_id。引用不到的变化，Agent 拒绝写入。`mechanism` 的取值由心理学组合同定义。

## 3. 接口

### 3.1 `step`：让角色在本轮行动

**StepRequest**

| 字段 | 说明 |
|---|---|
| `role_id`, `turn` | |
| `scene_context` | 本角色此刻可知的场景背景（不是全知背景） |
| `new_events` | 上次调用以来该角色新可见的 Event，可空 |
| `prev_state_id` | 上一状态引用，首轮为 null |
| `role_profile` | 角色档案；首轮必传，之后可省略【待确认】 |
| `allowed_kinds` | 本轮允许的行动类型，默认 `["speech","action"]` |

feedback-1015 写的是每轮传"过去该角色已知的聊天记录"。本合同建议只传增量，历史由 Agent 的 `memory` 保存；如果环境更方便传全量也可以，Agent 按 event_id 去重。【待确认】

**StepResponse**

| 字段 | 说明 |
|---|---|
| `role_id`, `turn` | |
| `actions` | ProposedAction 列表，可空（沉默也是有效选择） |
| `thought` | 私有内部解释，仅用于调试与分析 |
| `state` | 行动后的 AgentState 完整快照 |
| `delta` | StateDelta |
| `status` / `error` | `ok` 或 `error`；error 时 `actions` 为空 |

step 返回的"认知变化"只反映角色自己的打算（如"我决定先拖着"）。行动成没成功，要等环境裁决后经 perceive 回来。

### 3.2 `perceive`：让角色感知新事件并更新状态

- **PerceiveRequest**：`role_id`, `turn`, `events`, `prev_state_id`
- **PerceiveResponse**：`role_id`, `turn`, `state`, `delta`, `status`, `error`

perceive 不产生对外行动，角色想回应要等环境下一次调用 step。对应 feedback-1015 第 2 条"其他角色根据他的 action 更新认知字段"。

### 3.3 调用约定

1. **环境做可见性过滤**：只把 audience 含该角色的事件交给它。Agent 侧再校验一次，audience 不含自己的事件直接丢弃并告警。
2. **行动者本人也要 perceive 裁决结果**：A 的行动裁决后，环境产生 `type=outcome` 事件，audience 至少含 A。否则"反馈后写回"会断。
3. **thought 永不分发**：环境可以存日志，但不得放进任何 Event 的 `content`。
4. **失败不泄露内部文本**：Agent 出错时返回 `status=error` 和空 actions，不会把 thought 当台词输出。PersonaForge 原代码在这里会回退输出内心独白，我们会规避。

## 4. 一轮的标准时序（依次行动版）

```
环境                                         Agent(A)          Agent(B)
 │ step(A, new_events)            ─────────▶ │
 │ ◀──────── actions + thought + state/delta │
 │ 裁决 → e_01(A 的 speech), e_02(outcome)
 │ perceive(A, [e_02])            ─────────▶ │
 │ perceive(B, [e_01])            ──────────────────────────▶ │
 │ step(B, new_events=[])         ──────────────────────────▶ │
 │ ...
```

【待确认】一轮内是依次行动（上图），还是同时提交、统一裁决。

## 5. 调用形态与持久化

- v0 建议**同进程 Python 调用**，参数和返回值都是可 JSON 序列化的 dataclass，以后可以平滑换成 HTTP。【待确认】
- Agent 侧把每个 AgentState、StateDelta、prompt、模型配置、原始输出落盘到 `runs/<run_id>/<role_id>/`，可按 state_id 回放。
- 环境侧记录自己产生的全部 Event 和每次调用返回的 state_id 即可。

## 6. 验收

**Agent 模块保证：**
- 不可见事件不进入判断（自动化测试：给 A 一个 audience 不含 A 的事件，A 的 state 和 thought 都不得引用它）
- 每条状态变化都带证据
- 下一次 step 读取的是上一次 perceive 之后的状态
- 固定随机种子时，同一输入可复现

**希望环境组保证：**
- event_id 全局唯一、不复用
- `visibility.audience` 是裁决后的真实可见范围
- 行动裁决结果以 outcome 事件回到行动者

## 7. 需要场景组拍板的问题

1. 角色档案每轮都传，还是首轮传一次？
2. 历史传全量还是增量？
3. 一轮内依次行动还是同时行动？
4. 是否需要 `intent_note`？
5. 旁白、环境变化是否统一走 `type=narration`？
6. 同进程调用还是 HTTP？
7. role_id / event_id 的命名规则
8. 能否先给一个 2～3 个角色、3 轮以内的小剧本片段，作为联调固定样例？

## 附：Python 签名

```python
from dataclasses import dataclass, field
from typing import Literal, Optional

@dataclass
class Visibility:
    scope: Literal["public", "private"]
    audience: list[str]

@dataclass
class Event:
    event_id: str
    turn: int
    type: Literal["speech", "action", "narration", "outcome"]
    actor: str                      # role_id 或 "env"
    content: str
    visibility: Visibility
    target: list[str] = field(default_factory=list)
    outcome: Optional[dict] = None  # {"of_proposal", "status", "detail"}
    caused_by: Optional[str] = None

@dataclass
class ProposedAction:
    proposal_id: str
    kind: Literal["speech", "action"]
    content: str
    proposed_visibility: Visibility
    target: list[str] = field(default_factory=list)
    intent_note: Optional[str] = None

@dataclass
class StepRequest:
    role_id: str
    turn: int
    scene_context: str
    new_events: list[Event]
    prev_state_id: Optional[str]
    role_profile: Optional[dict] = None
    allowed_kinds: list[str] = field(default_factory=lambda: ["speech", "action"])

@dataclass
class StepResponse:
    role_id: str
    turn: int
    actions: list[ProposedAction]
    thought: str
    state: dict
    delta: dict
    status: Literal["ok", "error"] = "ok"
    error: Optional[str] = None

@dataclass
class PerceiveRequest:
    role_id: str
    turn: int
    events: list[Event]
    prev_state_id: Optional[str]

@dataclass
class PerceiveResponse:
    role_id: str
    turn: int
    state: dict
    delta: dict
    status: Literal["ok", "error"] = "ok"
    error: Optional[str] = None

class Agent:
    def step(self, req: StepRequest) -> StepResponse: ...
    def perceive(self, req: PerceiveRequest) -> PerceiveResponse: ...
```
