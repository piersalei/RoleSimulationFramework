# 一、关于文件接口合同_v0的修改意见

本部分第2、3节开头的表格保留原合同条目，供对照。

## 1. 完整来源覆盖

| 定义部分   | 需要说明的内容        | 例子                            |
| ------ | -------------- | ----------------------------- |
| 构念定义   | 该字段在心理学上是什么    | trust 是对特定对象可靠性的主观预期，不等于客观可靠性 |
| 状态归属   | 稳定、动态、关系或群体层   | 大五人格是稳定基线，当前信任是关系动态状态         |
| 数据表示   | 类型、维度、枚举、数值区间  | confidence 为 0 到 1，并且必须带证据来源  |
| 初始化    | 从档案如何取值，缺失时怎么办 | 档案没有情绪时，使用场景初始条件或中性先验         |
| 更新许可   | 允许由哪些事件和机制改变   | trust 只能由有关系意义的事件或修复证据改变      |
| 更新规则   | 方向、幅度、阈值、时间尺度  | 确证欺骗比一般失礼造成更大的信任下降            |
| 证据边界   | 角色能看到哪些信息      | 只能引用该角色可见的 event_id           |
| 评测定义   | 什么算一致、合理或错误    | 错误推断可以存在，但必须与可见证据和角色偏差相容      |
| 版本和兼容性 | 修改后如何追踪旧轨迹     | 字段删除、改名属于不兼容变化，需升级版本          |

## 2. 状态结构

### 2.1 stable：轨迹内不变

| 字段                      | 待心理学组确定                                |
| ----------------------- | -------------------------------------- |
| `traits`                | 用大五、HEXACO，还是只用文字描述；分数范围与量表来源          |
| `values`                | 自由文本还是固定词表（如 Schwartz 价值观）             |
| `core_goals`            | 数量上限；与 `goals_now` 的区分标准               |
| `values` / `core_goals` | 长轨迹中是否允许缓慢变化？若允许，应移到 dynamic 并给更低的更新速率 |

**目前可能问题**：仅可作为最小角色的粗粒度容器，不能对心智建模库进行由上到下的总概括，如果后期所有内容都塞进 traits，会产生三个问题。第一，工程无法知道某个数值是人格、能力、依恋还是发展功能，因而无法把它用于正确的行为约束。第二，心理学组无法区分主字段和派生字段，同一倾向可能被重复计权。第三，评测无法判断角色是违反了人格稳定性、能力上限、价值优先级，还是仅仅出现了合理的情境变化。

**拟改动方向**：保留几个顶层字段作为接口入口，但把它们改成可追溯的结构化对象。例如：

- identity：demographics、social_roles、resources、life_history；
- traits：personality、attachment、motivation_baseline、affective_capacities、social_cognition_71d、cognitive_style、developmental_position、personality_function；
- values：schwartz_priorities、moral_reasoning、cultural_orientation；
- core_goals：带优先级、稳定度和来源的目标对象；
- speech_style：表达基线与情境调节规则。

### 2.2 dynamic：可随事件更新

| 块              | 含义             | 待心理学组确定                                           |
| -------------- | -------------- | ------------------------------------------------- |
| `emotion`      | 当前情绪           | 离散标签、维度（valence/arousal），还是两者；intensity 是否需要；衰减规则 |
| `beliefs`      | 对世界的信念，可以是错的   | 置信度刻度；冲突信念怎么处理                                    |
| `goals_now`    | 当下目标与优先级       | 与 core_goals 冲突时如何处理                              |
| `relations`    | 对他人的关系评价       | 维度用 trust / closeness 是否够（权力、亏欠…）                 |
| `other_models` | 对他人心理的推断（心理理论） | 做到几阶：一阶"他想要什么"，二阶"他以为我怎么想"                        |

**目前可能问题**：
1. 上述五块只能支撑“事件进入—产生一个简单状态变化—输出行动”的最小原型，不能完整承载任意情境剧本中的多者互动。可以暂时作为顶层入口，但必须扩展成可追溯的子模块；否则注意、记忆、归因、策略、群体规范和修复过程只能被压缩成无法解释的信任或情绪变化；
2. 目前缺乏中间过程的演变记录，因此系统可能生成一条“信任下降”的 delta，却无法说明是因为确证欺骗、一般负面情绪、确认偏误、权力压迫还是旧伤记忆被激活。

**拟改动方向**：
1. dynamic 只表示角色当前可持续、可影响后续行为的心理状态。它不表示决策过程，不表示更新规则，也不等同于机制日志，可按状态性质组织为六个状态域：

- affect_state：当前情绪标签、效价、唤醒、强度、压力、威胁/奖赏激活，以及正在维持的情绪调节状态。
- cognition_state：当前信念、注意焦点、忽略项、归因/责任/可控性判断、自我评价和当前任务自我效能，以及对他人的心理推断；原 other_models 归入此域。
- goal_state：goals_now、价值与目标激活程度、动态目标承诺、可行性估计、目标冲突、短期优先级和当前行动指向；长期价值与 core_goals 基线仍保留在 stable。
- relation_state：针对每个互动对象的主观关系状态，包括 trust、closeness、dependence、commitment、power_asymmetry、harm_history、reputation 和 repair 状态。
- group_state：群体成员资格、身份显著性、规范显著性、联盟、群体内外边界和责任分配。
- policy_state：尚未完成的承诺、当前策略偏好、备用策略、切换条件、反馈后的策略权重和学习状态。

power_asymmetry 同时保存客观方向和角色主观感知，并分别标记可见性，未被角色获知的客观信息仅供系统或评测使用；relation_state.commitment 表示维持关系的承诺强度，policy_state 中的行动承诺则记录具体约定及履行状态，二者独立更新。

2. 每个事件拟执行顺序：建立角色可见事件集 → 检索相关 memory → 调用注意/评价/推断/选择等机制 → 生成候选状态变化 → 由更新算子校验并批量提交 StateDelta → 写入机制日志和结果反馈。这样 dynamic 能覆盖剧本中的多者互动影响，而不要求把每个心理学理论都变成一个字段。

3. 可采用“最小持久状态 + 可选机制轨迹”的方式：

- 状态 schema 只保存会影响后续行为、需要回放的动态变量；
- 机制日志保存本次事件中实际调用的过程、输入、候选策略和未选原因；
- 不需要持久化的中间计算可以只保留在 thought 或运行日志中；
- 只要某个中间变量会跨步影响未来，就必须登记为状态字段或记忆字段。

### 2.3 模块关闭与未知状态（补充）

stable、dynamic 的子模块及机制配置统一记录 status、来源、原因和版本：active 表示已启用且有可用值；unknown 表示已启用但证据不足，值用 null 并保留待补信息；disabled 表示本版已实现但被配置关闭；not_modeled 表示本版未建模。已建模但本轮未激活用 inactive；场景不适用另标 not_applicable。真实的 0、中性值或“无事件”空列表都是有效观测，不能代替上述状态。

只有已启用、适用且输入可用的机制分支可以计算或写回；unknown 仅能按登记的证据补全规则转为 active，缺失关键输入时跳过相关分支并标记信息不足。disabled、not_modeled 项不参与该构念的能力评分，覆盖率另行报告；重新启用须完成定义、初始化和规则校验。默认先验必须显式标为 default 并保留来源，不能冒充观测值。所有状态转换均留审计记录。

## 3. 更新机制

| mechanism         | 触发                | 可改的字段块           | 说明（初稿）           |
| ----------------- | ----------------- | ---------------- | ---------------- |
| `appraisal`       | 感知到与目标相关的事件       | emotion, beliefs | 按目标相关性、可控性评价事件   |
| `belief_revision` | 新信息补充或冲突旧信念       | beliefs          | 更新内容或 confidence |
| `tom_inference`   | 观察到他人言行           | other_models     | 推断他人意图、信念        |
| `relation_update` | 他人言行涉及自己          | relations        |                  |
| `goal_update`     | 目标达成、受阻，或情绪/信念变化后 | goals_now        |                  |
| `self_commit`     | 自己做出决定（step 时）    | goals_now        | 只反映打算，不代表结果      |
| `decay`           | 无新事件、时间推移         | emotion          | 情绪自然回落           |

**目前可能问题**：合同中的七个机制是工程侧按五个 dynamic 块设计的粗粒度写回分类，优点是简单、容易实现，也能覆盖一个最小闭环；但它们不是从决策机制库的十一个分类中推导出来的完整心理机制分类。当前表格把“评价”“推断”“关系变化”“目标变化”放在同一层级，粒度并不一致，混合了过程、写回、行动事件和时间过程。例如 appraisal 是评价过程，goal_update 是状态写回，self_commit 是行动日志，decay 是时间过程。

**拟改动方向**：
1. 按“可写入的状态对象”划分十一类：

- `emotion_update`：写入情绪标签、效价、唤醒、强度、压力和威胁/奖赏激活；重评、抑制、接纳等属于决策机制，只有结果通过此算子写回。
- `belief_revision`：写入或修订角色对世界、他人和自己的信念及其 confidence，必须有角色可见证据。
- `other_model_update`：写入角色对他人的目标、信念、意图和能力推断，允许错误但必须保留证据与置信度。
- `self_state_update`：写入自我评价、当前任务自我效能、羞耻、面子成本和责任评价等动态自我状态；不改写动力系统中的稳定自我效能基线。
- `relation_update`：写入本版本已启用的 trust、closeness、dependence、commitment、power_asymmetry、harm_history、reputation 和 repair 等关系状态；算子存在不代表所有候选字段均已上线。
- `group_state_update`：写入成员资格显著性、规范显著性、联盟、群体边界和责任分配等群体状态。
- `goal_update`：新增、完成、受阻、降级或切换 `goals_now`，并记录与 `core_goals` 的对应关系。
- `commitment_update`：形成、维持、兑现、违约、暂停或撤销行动承诺。
- `strategy_learning`：根据反馈更新策略权重、切换阈值或学习历史；不得直接改写稳定人格和价值基线。
- `memory_update`：形成、巩固、检索标记、再激活或改变记忆可及性；完整记忆条目仍保存在 `memory`。
- `decay_or_recovery`：按字段的时间尺度处理情绪恢复、激活消退、关系伤害显著性和策略权重恢复；没有规则的字段不得默认衰减。

每个更新算子都应有一张机制卡，至少说明触发事件、输入状态、可修改路径、变化方向、幅度等级、时间尺度、优先级、正例、反例、证据格式、软约束和评测指标。决策机制库的十一类过程通过 `decision_mechanisms` 进行映射，不需要为了对应更新算子而重新编写一套平行理论分类。

2. 每个事件按以下顺序运行：

- 建立该角色在当前时刻可见的事件集，排除对方隐状态、系统日志和其他角色私有信息。
- 读取 stable、dynamic 和相关 memory，调用决策机制库中的注意、记忆、归因、评价、推断、选择、表达或学习过程。
- 把中间判断、候选行动、候选状态变化和未选原因写入 mechanism_log，但暂不直接提交 dynamic。
- 由一个或多个更新算子生成候选 StateDelta，检查字段权限、证据、范围、顺序和冲突后批量提交。
- 保存提交结果、软约束标记、版本号和后续反馈，供下一事件和回放使用。

3. 多机制合并与分阶段提交：

同一角色的同一 event_id、event_phase 使用同一份已提交状态快照。动作选择先按规则卡声明的安全、能力、制度和承诺门槛筛选，再比较机制支持、目标价值、关系后果及执行成本；违约等行为须符合相应触发规则，选中动作不等于动作成功。写回允许一个事件产生多条变化：不同路径分别校验，同一路径先去重同一证据的重复贡献，再按规则卡指定的聚合方式、写权限和固定优先级裁决，不默认求和、平均或后写覆盖。动作竞争权重不能替代字段写权限。

候选变化按预先声明的依赖组原子提交；未声明分组时视为同一批。出现硬错或无法裁决的同路径冲突时，整组拒绝并保持原快照，其余独立组才可提交；软异常按第二部分第7点处理。日志保存候选、采纳/拒绝原因、优先级、输入/输出 state_id 和版本。重试以角色、事件、阶段及提交编号保证幂等；行动反馈、新证据或时间推进开启新阶段，使用最新已提交快照，禁止在同批内读取未提交候选并隐式级联。

4. 后续版本应全面纳入考虑的更新算子：

- emotion_regulation：重评、抑制、接纳、分心和恢复；
- learning_adaptation：反馈导致策略权重或期望更新；
- memory_consolidation：事件进入长期记忆、旧事件再激活；
- self_evaluation_update：自尊、自我效能、羞耻和责任评价变化；
- commitment_update：承诺形成、维持、违约和撤销；
- conflict_arbitration：价值、目标和关系冲突的暂时权衡；
- reputation_update：声誉和他人对角色的公共评价变化；
- norm_activation：规范显著性和个人义务被激活；
- repair_update：道歉、补偿、边界重建和宽恕后的关系变化。

这些项目不一定全部在 v1 作为独立更新算子上线：若其结果已经能由 v1 算子合法写回，可以先作为决策机制或机制日志标签；若结果需要跨事件影响未来行为，则必须在后续版本登记为独立状态字段或更新算子。

## 4. 三份材料汇总

三份材料可初步命名为“心理构念登记表”“角色状态说明”“心理变化规则表”。这三个名称分别回答“它在心理学上是什么”“角色状态怎样保存”“什么情况下怎样变化”：

### 4.1 心理构念登记表

语义主来源。每条记录使用唯一的 construct_id，写明构念定义、作用层级、时间性质、主字段/派生字段关系、证据边界、初始化含义、理论依据和评测判据；它不负责规定 JSON 类型，也不直接安排调用顺序。

### 4.2 角色状态说明

角色状态的机器可执行投影。它把登记表中已经确认的构念映射为字段路径、数据类型、维度、枚举、范围、必填/可空、默认结构、可见性和兼容规则，并由此生成运行时 JSON Schema；它不能新增未经登记的心理含义。

### 4.3 心理变化规则表

状态变化的执行投影。每条规则写明触发事件、角色可见证据、读取字段、允许写入的字段、变化方向、幅度区间、时间尺度、优先级、冲突处理、正例、反例、软约束和评测指标，并通过 construct_id 引用语义主来源。

### 4.4 补充说明

三份材料只允许有一个语义主来源：登记表中的 construct_id、定义版本和状态归属一旦确认，另外两份材料必须引用它；发现不一致时先冻结运行时发布，再由心理学组修订登记表并重新生成两个执行投影。材料协作流程固定为“登记—评审—投影—校验—发布—回放”：心理学组登记或修订构念，双方评审边界和可实现性，Agent 生成角色状态说明与规则表的机器投影，自动检查引用/范围/版本，使用小剧本回放，最后发布带四类版本号的合同快照。合同只列出当前启用的 construct_id、三份材料版本和兼容策略，不复制三份材料的全部正文；这样合同仍是追溯入口，而不是第四份互相矛盾的定义文件。

四类版本号分别为 construct_definition_version、state_schema_version、update_rule_version 和 evaluation_protocol_version；最后一项对应评测协议。每条轨迹及回放日志同时记录启用配置和 stable 快照标识，保证同一构念、规则与评测口径可追溯。

# 二、针对接口合同_v0待确认问题的答复

## 1. 人格框架：大五、HEXACO，还是纯文字？

人格框架分为三套方案，具体执行之后比较选出一套。三套人格方案 P1、P2、P3 是互斥的主编码方案。一个角色只从其中一套产生主人格变量，以免把不同理论中高度同义的维度叠加。成人依恋（Adult Attachment）是三套方案共用的关系取向层。P1 的大五领域与分面、P2 的十六个初级因素、P3 的 HEXACO 领域与分面均使用 -2—+2 的内部标准化连续分数，便于跨方案映射和相关采样；原量表分数必须先转换，不能把本区间称为原量表计分。P3 的荣格八功能以 0—1 的相对偏好权重表示并归一化为总和 1，主导、辅助、第三和劣势位置由权重排序派生；该权重表示偏好而非能力。

试跑采用“同一角色设定、三种主编码、独立运行、统一评测”的比较设计。每个方案输出相同的行为约束接口：高/低水平对应的倾向、阈值、敏感度、表达和恢复差异，以及不能直接推出的行为。用同一组场景比较三套方案的轨迹一致性、角色可区分性、跨场景稳定性、与外显行为匹配度和评测者一致率。

## 2. 情绪表示：离散、维度，还是两者？

情绪采用“离散类别 + 连续坐标”的组合。离散层回答角色把体验识别成什么；连续层采用情绪环形模型（Circumplex Model of Affect）的效价（Valence）—唤醒（Arousal）坐标，回答体验偏正或偏负、激活程度多高以及如何连续变化。支配/控制感（Dominance）作为可选第三坐标，只在权力、恐惧或愤怒场景中需要区分“同样负性高唤醒但控制感不同”时启用。

情绪状态的第一版字段固定为 label、valence、arousal、intensity、duration_hint 和 confidence；dominance 默认 not_modeled，只有规则卡声明权力、恐惧或愤怒场景需要区分控制感时才启用。离散标签表示角色对体验的识别，不能替代连续坐标；连续坐标用于衰减、峰值和轨迹比较，也不能反推唯一的离散情绪名称。emotion_update 先由事件评价和角色情绪能力产生候选变化，再由 decay_or_recovery 根据持续时间、恢复速度、再激活和调节结果处理后续变化。情绪标签可以改变而效价/唤醒连续移动，也可以保持同一标签但强度下降；每次变化都必须保留触发事件、可见证据、调节机制和时间尺度。

## 3. 关系维度用哪些？

目前第一版先采用“四项关系状态 + 一项关系历史”的最小向量：trust（对可靠性的预期）、closeness（情感接近/心理距离）、dependence（资源、照料或情感上的依赖）和 commitment（维持关系及履行关系义务的承诺），再加 harm_history（已发生伤害及其累积显著性）。前四项用 0—1 连续值并分别解释，harm_history 不只存一个分数，还要保存事件列表、严重度、是否承认、是否修复和最后激活时间。trust 主要由可靠性证据更新，closeness 由情感互动和边界事件更新，dependence 由资源/照料/替代性变化更新，commitment 由承诺形成、兑现和违约更新；同一事件可以影响多项，但不能使用同一百分比自动联动。

power_asymmetry 不与 trust 合并。它在第一版作为关系上下文的条件字段保存：场景若存在职位、资源、信息或身体能力的不对称，就必须记录客观方向和角色主观感知；没有权力差的场景可标记 not_applicable。这样既不把权力压缩成信任，也不要求每个普通关系凭空生成权力分数。

建议的附加字段按版本递进：v1.1 增加 repair_state、reputation、relationship_stage、reciprocity 和 boundary_state，并细化 power_asymmetry 内主观感知（perceived_power）的标定规则，不重复新增同义分数；v2 再考虑吸引/矛盾情感、亏欠与义务、第三方网络位置、群体规范压力和关系预期差异。附加字段先在心理构念登记表中定义，只有具备独立证据边界、跨事件影响和评测样本后才进入正式 schema。

## 4. 心理理论做到几阶？

心理理论能力在 v1 作为角色的“可用推理层级”约束，而不是一句身份标签。状态至少记录 tom_level、适用对象、证据来源、置信度和允许的推理任务；一阶表示能根据可见行为推断他人的信念/意图，二阶表示能推断“对方认为第三者怎样想”，更高层级只有在角色的年龄、发展位置、认知能力、经验和任务熟悉度共同支持时才启用。

年龄、学历或领导职位只能作为初始化证据之一，不能自动保证高阶心智化；儿童角色也可能在熟悉领域表现出局部能力，成人角色也可能因压力、疲劳、情绪或信息不足暂时降级。运行时由注意、记忆和情绪状态决定本次可实际调用的层级，错误推断允许存在，但必须与角色可见证据和能力上限相容。

## 5. 机制表是否完整，各自的理论依据和先后顺序？

原机制表不完整。按本文件的拟改动方向，v1 应按“可写入的状态对象”建立十一类更新算子：`emotion_update`、`belief_revision`、`other_model_update`、`self_state_update`、`relation_update`、`group_state_update`、`goal_update`、`commitment_update`、`strategy_learning`、`memory_update` 和 `decay_or_recovery`。这十一类在状态写回层面构成当前版本的完整最小集合，能够覆盖六个 `dynamic` 状态域以及目标、承诺、策略和记忆等需要跨事件保存的变量；它们不等同于十一种心理学理论，也不要求一个理论只对应一个算子。各更新算子的理论依据如下：

| 机制名 | 对应的理论依据 |
| --- | --- |
| `emotion_update` | 初级与次级评价模型（Primary and Secondary Appraisal）；情绪调节过程模型（Process Model of Emotion Regulation）；情绪环形模型（Circumplex Model of Affect）；威胁—奖赏反应政策（BAS、BIS、FFFS）；应对理论（Coping）。 |
| `belief_revision` | 信念更新与确认性加工（Belief Updating and Confirmation Processing）；启发式与系统性偏差（Heuristics and Biases）；归因、责任与意图判断；元认知监控与信心校准（Metacognitive Monitoring）；印象形成中的首因、近因和反例整合。 |
| `other_model_update` | 社会信息加工序列（Social Information Processing, SIP）；心智化执行模式（Mentalizing Modes）；归因与意图判断；印象形成与刻板化加工；信任与声誉更新。 |
| `self_state_update` | 社会比较与自我评价（Social Comparison）；社会学习理论（Social Learning Theory）中的自我效能；面子理论（Face Theory）；归因与责任判断；防御机制（Defense Mechanisms）。 |
| `relation_update` | 信任与声誉更新；社会交换与关系互依（Social Exchange and Interdependence）；依恋激活与支持交换（Attachment Activation and Support Exchange）；重复博弈、互惠和信号—承诺机制；权力行使与抵抗；关系修复、和解与宽恕。 |
| `group_state_update` | 社会认同理论（Social Identity Theory）；群体边界与身份切换；群体思维、责任分散和社会惰化；规范行为焦点理论（Focus Theory of Normative Conduct）；规范激活模型（Norm Activation Model）；角色、权威与制度信任；文化紧密性—松散性。 |
| `goal_update` | 评价模型中的目标相关性与目标激活；有限理性与满意化（Bounded Rationality and Satisficing）；计划行为理论（Theory of Planned Behavior, TPB）；实施意图（Implementation Intentions）；时间折扣与未来取向；施瓦兹价值体系提供的稳定优先级。 |
| `commitment_update` | 计划行为理论的意图形成；实施意图；信号、承诺与声誉；重复博弈与互惠；对话修复与承诺管理；社会交换与关系互依。 |
| `strategy_learning` | 社会学习理论；强化学习与结果预测误差（Reinforcement Learning）；探索—利用（Exploration–Exploitation）；反馈接受与适应速度；习惯与目标导向行动；认知灵活性与规则切换。 |
| `memory_update` | 记忆检索与时间窗口；社会学习中的保持阶段；印象形成中的首因/近因效应；伤害记忆、宽恕与和解；记忆保持、再激活和可及性变化。 |
| `decay_or_recovery` | 情绪调节过程模型；压力应对与恢复（Coping and Recovery）；反刍、恢复与自我控制（Rumination, Recovery and Self-Control）；防御的维持与转换；关系修复、宽恕与和解；按字段时间尺度管理记忆保持和激活消退。 |

先后顺序是逻辑依赖顺序，不能把十一项算子逐行执行并读取彼此尚未提交的结果。每个事件阶段先确定角色可见证据，读取已提交的 `stable`、`dynamic` 和相关 `memory`，经注意、检索、评价、归因和心智化形成候选判断，再激活目标、价值及规范，筛选行动并形成承诺。过程之间可以显式传递中间判断，但这些判断仍是候选，不是已经生效的状态或客观事实；各算子对同一路径的 before 均取自该阶段的共同快照。

行动前的状态变化经校验提交后执行行动与表达；行动结果、他人反应、新证据或权力变化到达时，开启新的 event_phase，重新核定可见性并读取最新提交状态，可再次调用情绪、信念、目标、关系或群体算子。时间推进须登记为可审计的时间事件，再按规则执行恢复或衰减；不得默认冲淡信念、伤害事实或稳定基线。合并、冲突与原子提交按第一部分第3节执行，实际调用、中间判断、候选与最终变化、未选原因、异常标记及四类版本号统一写入 `mechanism_log`。

## 6. 单步变化量、衰减速率、人格调节系数的初始值；定量规则还是定性规则交给模型判断？

定量规则可复现但可能僵硬，定性规则灵活但易漂移，建议采用混合方案：程序规定范围、事件等级和硬上限，模型在范围内选择具体值。人格调节系数不应直接写成“神经质乘以变化量”。应先规定它影响的是敏感度、峰值、持续时间还是恢复速度，并通过标定样本检查是否过度放大人格差异。

混合方案的执行顺序固定为：规则卡先声明该字段受影响的是敏感度、峰值、持续时间还是恢复速度，并给出事件等级、典型区间和硬上限；角色参数与关系/场景参数再把模型可选值定位到区间内；模型提交具体变化及理由；程序完成范围、权限、证据和软约束校验。不同字段可以采用不同的受影响性质，不能用一个“人格调节系数”统治所有状态。

每次校准至少比较同一事件下的低/中/高敏感度角色，分别检查峰值是否过大、持续是否过长、恢复是否过慢和跨字段联动是否被放大。校准发现人格差异被放大到足以掩盖事件差异时，优先调整敏感度映射或事件区间，而不是直接修改角色的人格基线。

## 7. 越界和软约束违反时拒绝还是标记？

采用“硬错拒绝、软错标记、重大事件可豁免但必须说明”的三级策略。结构/字段范围越界、不可见证据、未登记算子、普通 StateDelta 修改 stable、无写权限或无法解析，均按硬错拒绝其依赖组；典型区间外、衰减过慢、调节过强或跨字段心理变化不典型，在硬校验通过后可提交并标记 soft_violation。重大事件仅可豁免规则卡明确允许的软边界，记录 exception_approved、证据、角色参数、批准规则和复核结果，不能豁免硬错。长期基线换版另走第13题的审核发布流程。所有拒绝与标记均进入回放日志，不静默截断或覆盖。

## 8. 推断出的 stable 字段是否需要人工确认？

人工确认采用“影响分层”。身份/年龄/职业等档案明写字段可自动进入候选初始状态；会改变行为约束、评测结论或能力上限的高影响 stable 字段须经过心理学组审核或规则校验。

## 9. 评测维度、量表和标注流程？

第一版先拟采用“自动审计 + 人工评分”的固定流程：自动审计先筛出结构错误并生成报告；人工对通过审计的样本按第三部分的固定维度及 0—3 级锚点评分，重点检查证据充分性、方向/幅度合理性、角色一致性和轨迹连续性；每项都填写最小理由和对应 event_id。硬错及被拒候选仍纳入错误率和相关维度的零分统计；抽取一部分由第二位评测者复标，统计一致率并用校准集统一评分标准。

## 10. 能否基于环境组的联调小剧本，给 2～3 个角色的完整 stable 设定，以及 1 个角色的"标准答案"状态轨迹，作为第一批测试样例？

可提供涉及角色的完整角色构建设定（即心智建模库和决策机制库中的最小必要维度） + 指定角色的合理行为逻辑发展（及合理分歧轨迹），心理学组给出的合理行为逻辑发展按“如果观察到哪些证据—会激活哪些过程—候选反应有哪些—哪些反应仍然合理—哪些反应属于反例”书写。

另外为使 Agent 能执行，交付包可再增加三份结构化附件：场景事件表、角色可见性表、状态变化验收表。场景事件表为每个事件提供唯一 event_id、发生时间、公开内容、参与者、客观结果、可被各角色观察到的行为和证据可靠度；角色可见性表按 role_id × event_id 标记 observed、heard、inferred、not_visible，并列出不可使用的信息。

## 11. 字段`values`自由文本还是固定词表（如 Schwartz 价值观）

`values`采用“固定构念词表＋说明文本”。以施瓦兹十九项价值为主词表，保存相对优先级、排序、冲突阈值和可让步范围；v1建议使用非负且总和为1的权重，另存总体价值投入度。自由文本解释角色化含义和来源，不自行新增运行时维度。道德推理与文化取向分设子模块，同义构念不重复计权；事件中的相关性和激活强度放入`dynamic`，不覆盖稳定权重。

## 12. `core_goals`的数量上限；与 `goals_now` 的区分标准；`goals_now`与`core_goals`冲突时如何处理

v1建议保留1—3个主核心目标，每个可有1—2个支持子目标。`core_goals`是跨多次互动组织长期结果，`goals_now`是针对当前事件或短期窗口，完成、受阻或出现新证据即可替换。目标保存来源、优先级、稳定度及上下位链接。

二者冲突时，由选择机制比较安全与能力边界、价值底线、现实成本和关系义务，记录暂停、换方案或让步的理由；`goal_update`只调整当前目标、动态承诺或修订候选，不能为解释一次行为改写核心目标。

## 13. `values` / `core_goals`长轨迹中是否允许缓慢变化？

允许，但普通事件只改变价值或目标的激活、承诺、可行性和策略，稳定基线仍保留在`stable`。长期经验、持续学习、明确训练或身份转折达到规则卡规定的时间与证据门槛后，先记录修订候选，经心理学组审核及兼容校验，再通过版本迁移创建新的`stable_snapshot`；保留旧快照、触发证据、变更理由和重新评测要求。普通`StateDelta`始终不得写`stable`，也不把价值整体移入`dynamic`。

## 14. `beliefs`置信度刻度；冲突信念怎么处理

v1建议将`confidence`定义为对具体命题为真的主观确信，取0—1：0为确信不成立，0.5为正反未定，1为确信成立，不等于客观正确率；未形成判断用`unknown`和null，不默认填0.5。每条信念保留belief_id、对象、适用情境与时间、可见来源和冲突组。冲突时可并存待证、分化情境、降低确信或悬置，并记录本轮采纳项；不强制平均、归一或覆盖历史。`belief_revision`按证据质量、先验和反证权重更新；角色暂时隔离矛盾也须显式留痕。

# 三、评测工作相关

## 3.1 数据层次

1. 字段层：初始状态是否完整、类型正确、范围正确、来源可追溯。
2. 变化层：每条 StateDelta 是否有证据、机制、方向和理由。
3. 轨迹层：一系列变化是否形成连续、可解释的心理轨迹。
4. 对照层：不同角色、不同模型、不同机制开关面对同一输入时是否产生可解释差异。

## 3.2 主要评测维度

固定评测维度为：字段有效性、证据与可见性、机制与写回相容性、稳定一致性、动态合理性、角色可区分性、外显行为与隐状态匹配、错误推断的合理性、轨迹可追溯性。字段有效性和可见性由自动审计先判定；其余维度由人工依据样本包评分。

## 3.3 建议的标注单位和量表

首批标注不应只抽 20—30 条孤立 delta，最好组成有上下文的样本包：事件前状态、触发事件及角色可见信息、模型输出和 thought、事件后状态、全部候选与最终 StateDelta、拒绝原因、相关历史事件，以及供评测者查看的对方真实状态。对方真实状态只用于对照分析，判断角色推断是否合理仍限于该角色可见证据，不能以推断符合真相与否代替合理性评分。每条变化可采用 0—3 级评分，若存在硬错，相关维度直接记 0，并在表单中选择硬错类型：

- 0 表示结构/证据/理论上无法成立或完全无法解释；
- 1 表示方向可能相关但缺少关键证据、机制或幅度依据；
- 2 表示基本符合角色与事件，只有轻微遗漏或表述问题；
- 3 表示证据可见、机制匹配、方向和幅度合适、前后状态连续且能解释外显行为。

轨迹级评分再分别评价 stable 一致性、动态连续性、因果可追溯性、角色可区分性、心理理论符合度、外显行为与隐状态匹配，以及错误推断的合理性。

## 3.4 自动评估和真人基线

自动评估适合做结构检查、数值检查、证据可见性检查、规则覆盖检查和初步异常筛选；不宜单独决定“一个真实的人会不会这样变化”。真人基线不是第一版的硬性前置条件。建议先用心理学组的标准答案和人工标注校准 Agent，再用少量真人或专家对同一剧本作答，最后在需要对外宣称“接近人类行为”时扩大真人基线样本。

评测协议 v1 固定为“样本包—自动审计—人工评分—复标校准—报告回写”五个阶段。心理学组先冻结评测维度、评分锚点、可见数据范围和版本号；Agent 组按同一模板导出样本包，禁止评测者临时改变评分口径。
