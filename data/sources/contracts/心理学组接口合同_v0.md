# 角色 Agent ⇄ 心理学组 状态与更新机制合同 v0

## 0. 一句话

心理学组定义"角色心里有哪些东西、哪些会变、因为什么变、变多少算合理"；Agent 模块把这些定义落成可运行、可审计、可回放的代码。工程侧不自创心理构念，心理学组不需要关心调用时序和环境接口。

## 1. 职责边界

| 事项 | 心理学组 | Agent 模块 |
|---|---|---|
| 选用哪些心理构念、理论依据 | ✔ | |
| 字段定义、取值范围、初始化规则 | ✔ | 实现与校验，提可实现性意见 |
| 哪些字段稳定、哪些可变 | ✔ | |
| 更新机制（什么事件触发什么变化） | ✔ 定义规则 | ✔ 实现 |
| 变化幅度、速率等参数 | ✔ | 实现并校验 |
| prompt / 规则代码、模型调用、结构化解析 | 审阅 | ✔ |
| 状态落盘、回放、自动检查 | | ✔ |
| 评测标准与人工标注 | ✔ | 提供数据与工具 |
| 版本发布 | 发布 `psychology_version` | 记录到每条状态 |

原则：Agent 里出现的每一个心理字段和更新机制，都要能对应到本合同里的一条定义。没有定义的不上线。

环境组只把 `stable` / `dynamic` 当不透明 JSON 存档，本合同的改动不需要环境组同步。

## 2. 状态结构

AgentState 外层（`stable` / `dynamic` / `memory`、`state_id`、版本号）已在环境组合同 2.4 固定。本合同定义 `stable` 和 `dynamic` 的内部。以下是工程侧**初稿建议**，字段名和取值都等心理学组改。

### 2.1 stable：轨迹内不变

```json
{
  "identity":     {"name": "王伯", "age": 72, "role_in_scene": "一楼老住户"},
  "traits":       {"framework": "BigFive",
                   "scores": {"O": 0.3, "C": 0.7, "E": 0.4, "A": 0.6, "N": 0.6}},
  "values":       ["节俭", "不给子女添麻烦"],
  "core_goals":   ["维持现有生活秩序"],
  "speech_style": "说话慢，爱用反问，不直接拒绝"
}
```

| 字段 | 待心理学组确定 |
|---|---|
| `traits` | 用大五、HEXACO，还是只用文字描述；分数范围与量表来源 |
| `values` | 自由文本还是固定词表（如 Schwartz 价值观） |
| `core_goals` | 数量上限；与 `goals_now` 的区分标准 |
| `values` / `core_goals` | 长轨迹中是否允许缓慢变化？若允许，应移到 dynamic 并给更低的更新速率 |

stable 在一条轨迹内只读，任何写入都被拒绝并告警。

### 2.2 dynamic：可随事件更新

```json
{
  "emotion": {"label": "焦虑", "valence": -0.4, "arousal": 0.5, "intensity": 0.6},
  "beliefs": {
    "elevator_fee": {"content": "每户约200元", "confidence": 0.6, "source": ["e003_02"]}
  },
  "goals_now": [{"goal": "先问儿子意见", "priority": 0.8}],
  "relations": {
    "li_ayi": {"trust": 0.5, "closeness": 0.6, "note": "邻居多年"}
  },
  "other_models": {
    "li_ayi": {
      "inferred_goal": "推动加装电梯，想拉我签字",
      "inferred_belief_about_me": "以为我会同意",
      "confidence": 0.4,
      "source": ["e003_02"]
    }
  }
}
```

| 块 | 含义 | 待心理学组确定 |
|---|---|---|
| `emotion` | 当前情绪 | 离散标签、维度（valence/arousal），还是两者；intensity 是否需要；衰减规则 |
| `beliefs` | 对世界的信念，可以是错的 | 置信度刻度；冲突信念怎么处理 |
| `goals_now` | 当下目标与优先级 | 与 core_goals 冲突时如何处理 |
| `relations` | 对他人的关系评价 | 维度用 trust / closeness 是否够（权力、亏欠…） |
| `other_models` | 对他人心理的推断（心理理论） | 做到几阶：一阶"他想要什么"，二阶"他以为我怎么想" |

约束：
- `beliefs`、`other_models` 每一项必须带 `source`，只能引用本角色可见的 event_id
- 数值字段默认闭区间 `[0,1]`，`valence` 为 `[-1,1]`【待确认】
- 角色对他人的推断与对方真实状态不一致是允许的，错误推断本身就是研究对象

## 3. 更新机制

每条状态变化必须声明 `mechanism`，取值来自下表。Agent 不接受未登记的 mechanism。

| mechanism | 触发 | 可改的字段块 | 说明（初稿） |
|---|---|---|---|
| `appraisal` | 感知到与目标相关的事件 | emotion, beliefs | 按目标相关性、可控性评价事件 |
| `belief_revision` | 新信息补充或冲突旧信念 | beliefs | 更新内容或 confidence |
| `tom_inference` | 观察到他人言行 | other_models | 推断他人意图、信念 |
| `relation_update` | 他人言行涉及自己 | relations | |
| `goal_update` | 目标达成、受阻，或情绪/信念变化后 | goals_now | |
| `self_commit` | 自己做出决定（step 时） | goals_now | 只反映打算，不代表结果 |
| `decay` | 无新事件、时间推移 | emotion | 情绪自然回落 |

请心理学组对每种机制给出：
1. 理论依据（文献或模型）
2. 触发条件：什么事件会触发，什么不会
3. 变化方向和幅度的规则，至少是定性规则（如"被欺骗证据确凿时 trust 下降，降幅大于普通负面事件"）
4. 机制之间的先后顺序（如 appraisal 先于 relation_update）
5. 2～3 个正例和 1 个反例（不应发生变化的情形）
6. 是否缺机制（如自我调节、动机冲突）

Agent 模块把规则写进 prompt 或规则代码，实现后发回心理学组审阅。

### 3.1 硬约束（Agent 侧强制执行，违反即拒绝写入）

1. **证据约束**：每条 change 的 `evidence` 只能引用本角色可见的 event_id 或自己的 proposal_id，不可为空。
2. **stable 不可写**：path 以 `stable.` 开头一律拒绝。
3. **字段白名单**：每个 mechanism 只能改上表列出的字段块。
4. **取值范围**：越界直接拒绝，不做截断（截断会掩盖模型错误）。【待确认】

### 3.2 软约束（需要心理学组给参数）

- **单步最大变化量**：如 `trust` 单步变化不超过 0.3，除非事件被标记为重大
- **情绪衰减**：无新事件时每轮 intensity 回落多少
- **人格调节**：如 neuroticism 高的角色负面 appraisal 幅度更大，系数多少

违反软约束时先写入并标记 `flag: "soft_violation"`，留给评测分析，不直接拒绝。【待确认】

### 3.3 StateDelta 中的一条 change

格式在环境组合同 2.5 定义，心理学相关的是 `mechanism` 和 `reason`：

```json
{"path": "dynamic.relations.li_ayi.trust",
 "before": 0.5, "after": 0.35,
 "evidence": ["e004_01"],
 "mechanism": "relation_update",
 "reason": "李阿姨当众提了我欠物业费的事",
 "flag": null}
```

`reason` 是模型生成的自然语言解释，供人工评测用，不参与程序逻辑。

## 4. 角色档案到初始状态

环境组首轮给出角色档案（自然语言或半结构化）。

- 心理学组给出：每个字段从档案中怎么取值；档案没写时的默认值或推断规则
- Agent 模块实现：自动抽取 → 输出初始 state → 标记每个字段是"档案明写"还是"推断"
- 【待确认】推断出的 stable 字段是否需要人工确认后才能开跑

## 5. 评测（心理学组主导）

Agent 模块提供：
- 每条轨迹的完整 AgentState 序列、StateDelta、thought、原始模型输出
- 同一输入在不同 prompt / 模型 / 机制开关下的对照结果
- 按角色、按机制筛选 delta 的查看与逐条打分工具
- 自动检查报告：越界、无证据变化、stable 被改、引用不可见事件、软约束违反

希望心理学组定义：
1. **一致性**：言行是否符合 stable 设定
2. **合理性**：每条 change 是否"一个真实的人会这样变"
3. **可区分性**：不同人格面对同一事件，变化是否有可预期的差异
4. **心理理论**：推断是否有依据，错误推断是否"错得合理"；`other_models` 与对方真实状态怎么对比
5. 每个维度的打分刻度和标注说明
6. 首批人工标注样本（建议 20～30 条 delta），用来校准自动评估
7. 是否需要真人基线（让被试面对同一剧本作答）

## 6. 版本管理

- 字段定义版本记为 `schema_version`（如 `state-v0`），更新机制版本记为 `psychology_version`（如 `psy-v0`），每个 AgentState 都带这两个字段
- 心理学组改动时升版本号并附变更说明；旧轨迹不重写，按版本标注是否可比
- 只新增字段属于兼容变更；改名、删除属于不兼容变更，Agent 需同步发版
- 字段定义的唯一来源：本合同确认后由 Agent 模块生成的 JSON Schema 文件

## 7. 需要心理学组拍板的问题

1. 人格框架：大五、HEXACO，还是纯文字？
2. 情绪表示：离散、维度，还是两者？
3. 关系维度用哪些？
4. 心理理论做到几阶？
5. 机制表是否完整，各自的理论依据和先后顺序？
6. 单步变化量、衰减速率、人格调节系数的初始值；定量规则还是定性规则交给模型判断？
7. 越界和软约束违反时拒绝还是标记？
8. 推断出的 stable 字段是否需要人工确认？
9. 评测维度、量表和标注流程？
10. 能否基于环境组的联调小剧本，给 2～3 个角色的完整 stable 设定，以及 1 个角色的"标准答案"状态轨迹，作为第一批测试样例？

## 附：Python 结构（初稿，随本合同修订）

```python
from dataclasses import dataclass, field
from typing import Literal, Optional

Mechanism = Literal["appraisal", "belief_revision", "tom_inference",
                    "relation_update", "goal_update", "self_commit", "decay"]

@dataclass
class StableState:
    identity: dict
    traits: dict                     # {"framework": str, "scores": dict[str, float]}
    values: list[str]
    core_goals: list[str]
    speech_style: str = ""

@dataclass
class Emotion:
    label: str
    valence: float                   # [-1, 1]
    arousal: float                   # [0, 1]
    intensity: float                 # [0, 1]

@dataclass
class Belief:
    content: str
    confidence: float                # [0, 1]
    source: list[str]                # 可见 event_id，不可为空

@dataclass
class Goal:
    goal: str
    priority: float                  # [0, 1]

@dataclass
class Relation:
    trust: float                     # [0, 1]
    closeness: float                 # [0, 1]
    note: str = ""

@dataclass
class OtherModel:
    inferred_goal: Optional[str]
    inferred_belief_about_me: Optional[str]
    confidence: float                # [0, 1]
    source: list[str]                # 可见 event_id，不可为空

@dataclass
class DynamicState:
    emotion: Emotion
    beliefs: dict[str, Belief] = field(default_factory=dict)
    goals_now: list[Goal] = field(default_factory=list)
    relations: dict[str, Relation] = field(default_factory=dict)
    other_models: dict[str, OtherModel] = field(default_factory=dict)

@dataclass
class Change:
    path: str                        # 如 "dynamic.relations.li_ayi.trust"
    before: object
    after: object
    evidence: list[str]              # 不可为空
    mechanism: Mechanism
    reason: str
    flag: Optional[Literal["soft_violation"]] = None
```
