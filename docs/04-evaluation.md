|---|---|---|

## 真实模型实验设计

首轮建议 6–10 个审定角色 × 3 类情境 × 2–3 个条件变化 × 多次独立运行。规模是起步建议，不是已完成样本；正式样本量应依据先导方差、预算与预注册问题决定。

优先设置以下对照：

1. 相同人物、相同事件，只改变压力。
2. 相同人物、相同世界真值，只改变角色收到的信息。
3. 相同人物和信息，只改变过去是否兑现承诺。
4. 相同情境、不同人物，检查可解释差异和表面措辞差异。
5. 提供纠正证据，观察是否合理修正，而不是固守最初错误解释。

方法对照建议为：静态人物提示；人物提示 + 外部状态；人物提示 + 外部状态 + 机制调度。当前只有 `profile_only` 与 `mechanisms` 两个入口，后者同时增加状态和机制，不能将二者差异全部归因为机制；中间消融组与真正的实验调度器尚待实现。

固定基础模型、可见信息、任务目标、输出长度上限与重试协议。分别报告调用次数、token/延迟、失败率；两阶段调用成本单列。真实模型即使设置相同温度也不保证精确复现，应保存实际输入输出。

## 外显行为盲评

裁判只看同等范围的角色设定与可见交互，不向某一方法额外提供内部独白、机制卡、分数或自我辩护。打乱方法标签。`public.jsonl` 是公开行为导出；复杂私有信息任务应统一提供该角色实际可见的信息包，不从系统真值补全。

| 维度 | 评价问题 |
|---|---|
| 画像一致性 | 表现能否由稳定倾向、情境和冲突解释？是否无理由改写核心设置？ |
| 情境敏感性 | 压力、权力、关系、资源变化是否产生合理而非任意变化？ |
| 知识边界 | 是否使用了角色未获得的信息？是否把推断当事实？ |
| 状态连续性 | 前轮经历是否影响后轮？明确新证据能否修正原判断？ |
| 行为—结果一致 | 台词是否兑现已选动作？是否把提议虚报为成功？ |
| 多样性与非刻板化 | 是否存在多种合理反应？是否仅复述同一种心理标签？ |

每个问题允许多个可接受行为及条件化解释。不要把某位评审最喜欢的回答当唯一真值。先独立评分，再对分歧复核；报告评审一致性、个体分布和失败例，不只报平均分。

## 内部机制审计

另用 `audit.jsonl` 检查触发是否符合条件、引用事件是否可见、状态变更是否有依据、未选机制是否被合理抑制。内部审计只支持流程解释，不能直接加到外显行为效果分中。

待补测的实质风险：语义幻觉、表达与动作不一致、长轨迹上下文增长、自动线索提取误差、提示字段之间的重复加权、跨人物/情境泛化。v0.1 没有声称解决这些问题。
