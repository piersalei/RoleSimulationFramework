# 评测方案

本文说明**怎么评**：两种质量分开记、真实模型实验怎么设对照、外显行为怎么盲评、内部机制怎么审计。已经做过哪些检查、结果如何，见 [15-verification-log.md](15-verification-log.md)。

当前结论只到"本地工程检查"和单次"模型实验"这一层；评测协议本身尚未冻结（待办见 [plan/02](../plan/02-psychology-questions.md)）。

## 分开记录两种质量

| 质量 | 看什么 | 不应如何替代 |
|---|---|---|
| 工程正确性 | 可见性、状态更新来源、字段稳定、动作合法性、可复现性 | 工程测试通过不能说明角色像人 |
| 模拟有效性 | 跨情境倾向、条件性变化、行为可接受性、与参考材料一致 | 机制名写进日志不能说明行为真的符合机制 |

## 真实模型实验设计

首轮建议 6–10 个审定角色 × 3 类情境 × 2–3 个条件变化 × 多次独立运行。规模是起步建议，不是已完成样本；正式样本量应依据先导方差、预算与预注册问题决定。

优先设置以下对照：

1. 相同人物、相同事件，只改变压力。
2. 相同人物、相同世界真值，只改变角色收到的信息。
3. 相同人物和信息，只改变过去是否兑现承诺。
4. 相同情境、不同人物，检查可解释差异和表面措辞差异。
5. 提供纠正证据，观察是否合理修正，而不是固守最初错误解释。

方法对照建议为：静态人物提示；人物提示 + 外部状态；人物提示 + 外部状态 + 决策过程判断。现有三种消融模式 `profile_only` / `profile_state` / `profile_state_mechanisms`（`--mode`），状态与决策过程的贡献可分开比较；三种模式下状态都照常计算，只有提示和输出格式不同；真正的实验调度器（多角色、多场景、多模型批量运行）尚待实现。

固定基础模型、可见信息、任务目标、输出长度上限与重试协议。分别报告调用次数、token/延迟、失败率；各阶段（S1 / S2 / S3 / 表达）的调用成本单列。真实模型即使设置相同温度也不保证精确复现，应保存实际输入输出。

## 外显行为盲评

裁判只看同等范围的角色设定与可见交互，不向某一方法额外提供内部独白、决策过程判断、分数或自我辩护。打乱方法标签。评审包里每个单元的 `role_visible_trace.jsonl` 是该角色实际看得到的记录；复杂私有信息任务应统一提供该角色实际可见的信息包，不从系统真值补全。

| 维度 | 评价问题 |
|---|---|
| 画像一致性 | 表现能否由稳定倾向、情境和冲突解释？是否无理由改写核心设置？ |
| 情境敏感性 | 压力、权力、关系、资源变化是否产生合理而非任意变化？ |
| 知识边界 | 是否使用了角色未获得的信息？是否把推断当事实？ |
| 状态连续性 | 前轮经历是否影响后轮？明确新证据能否修正原判断？ |
| 行为—结果一致 | 台词和动作是否兑现计划？是否把提议虚报为成功？ |
| 多样性与非刻板化 | 是否存在多种合理反应？是否仅复述同一种心理标签？ |

每个问题允许多个可接受行为及条件化解释。不要把某位评审最喜欢的回答当唯一真值。先独立评分，再对分歧复核；报告评审一致性、个体分布和失败例，不只报平均分。

## 内部机制审计

另用运行目录里的轨迹（`trace/<互动>/<角色>/phases.jsonl`、`model_calls.jsonl`）和自动审计（`audit_report.*`）检查：状态链是否连续、引用的记录是否可见、写入是否经登记表授权、提示是否隔离、隐瞒内容是否进了表达、稳定画像是否不变。每条写入都能追溯到一个变化槽位、一个判断和一个区间，选值理由也落盘；判断本身是否符合条件（例如信任理由里的事实对不对），要等各过程的输出字段确定（F2）后才能部分自动检查，现在只能人工看。内部审计只支持流程解释，不能直接加到外显行为效果分中。

待补测的实质风险：语义幻觉、表达与动作不一致、长轨迹上下文增长、自动线索提取误差、提示字段之间的重复加权、跨人物/情境泛化。v0.1 没有声称解决这些问题。
