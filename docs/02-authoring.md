# 心理学与工程的交付接口

心理学同学最有价值的交付是**字段含义、触发条件、行为锚点与反例**。工程侧再将其转为数据结构、调度和验证；暂不要求心理学同学直接写代码。

## 人物制作

复制 `examples/cautious.json`，修改人物身份、公开描述、自我理解、相关分面和少量需要/价值。保留明确未实现模块。运行 `validate` 后再 `compile` 检查三个视图。模板内的数值是虚构示例，应逐项审定，不是默认人群常模。

| 交付内容 | 必须说明 | 好的示例 |
|---|---|---|
| 主字段 | 构念、尺度、来源、是否测量 | “焦虑分面 1.2，角色设计值，非量表结果” |
| 自我理解 | 角色会如何解释自己 | “我只是需要弄清楚再答应” |
| 通常倾向 | 概率性而非永久绝对规则 | “高不确定任务中更可能索取证据” |
| 触发条件 | 可见线索与关系条件 | “重要合作方连续两次未兑现承诺” |
| 压力变化 | 能力/策略如何受负荷影响 | “先减少承诺范围，仍不凭空推断恶意” |
| 例外 | 何时应改变默认反应 | “出现可核对的兑现记录后恢复小范围合作” |
| 可观察信号 | 台词、动作、延迟、选择 | “请求回执、提出分阶段交付、拒绝不可控承诺” |
| 不应出现 | 可证伪的错误表现 | “未收到记录便宣告对方已兑现” |

未知数值保留缺失理由。当前代码为了保持小而明确的可执行结构，要求 P1 30 分面全部赋值；示例未重点设定项为显式合成中性 `0`，与 71 维的“定义缺失、未赋值”不同。未来材料抽取模式需扩展 nullable 字段及缺失策略，不能将缺失测量静默写成中性。

## 机制卡审定模板

```yaml
id: trust_revision
source: 决策机制库 3.4
status: proposed
psychological_hypothesis: 重复失约后更倾向先核查，兑现证据可支持有限恢复
stable_inputs:
  - 核查倾向
  - 关系的重要性
dynamic_inputs:
  - 对该对象的可靠性判断
  - 可见的承诺与兑现历史
trigger:
  observable_condition: 两次明确承诺均未在约定时间兑现
  insufficient_condition: 仅听到别人抱怨此人不可靠
options: [核查, 缩小授权, 协商修复, 暂停合作]
exceptions:
  - 角色观察到不可控外部障碍
  - 紧急共同目标要求暂时继续合作
updates:
  - 可靠性判断改变，不能据此直接覆盖善意或能力判断
observable_anchors:
  - 请求具体兑现证据
  - 提出可逆的小范围合作
counterexample:
  - 一次道歉就无依据地完全恢复信任
reviewer: 待填写
calibration: 待实验；不得把模板当已验证规律
```

该模板是供讨论的设计格式；v0.1 注册表位于 `rolesim/mechanisms.py`，并不直接读取上述 YAML。先确定规则，再决定是否迁移为数据驱动的执行配置。

## 当前字段到底用于哪里

| 字段 | 当前用途 | 未实现部分 |
|---|---|---|
| 30 分面 | 完整校验；4 分面编译条件化语句；合作分面参与卡片排序 | 其余分面的完整行为投影 |
| 依恋两轴 | 存储与范围校验 | 依恋特异触发、关系工作模型 |
| 需要、价值 | 控制器可见的稀疏权重 | 需要满足度、目标效用、价值冲突求解 |
| 情绪敏感度/恢复 | 参与事件后紧张更新 | 多维情绪、调节策略成功率 |
| 核查偏好 | 条件化语句、verify 排序 | 自然语言证据强弱与误信修订 |
| 表达直接性 | 条件化风格、boundary 排序 | 更丰富语言风格与残差建模 |
| 71 维能力 | 明确缺失状态 | 定义、评分、能力门和压力影响 |
| 发展、功能、文化 | `deferred_modules` 记录原因 | 全部待审定与实现 |

## 第一批共同审定材料

建议每位人物准备三个短场景：低压力基准、同内容高压力、出现纠正证据后的恢复。另做信息可见/不可见对照。每个场景允许多个可接受行动，并要求说明“什么条件下属于合理变化”。

首批需要补齐：原引用的 71 维定义文件；两到三个真正希望研究的角色材料；五张机制卡的强/弱触发和例外；哪些字段能给角色知道、哪些仅供系统施加行为约束。服务器地址与模型选择是后续配置，不影响本地结构审定。
