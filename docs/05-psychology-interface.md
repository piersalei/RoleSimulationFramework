# 心理学组的交付接口

心理学同学最有价值的交付是**字段含义、触发条件、行为锚点与反例**。工程侧再将其转为数据结构、调度和验证；暂不要求心理学同学直接写代码。

本文是写给心理学组的：交付什么、按什么格式、哪些字段现在真正被用到、哪些还只是占位。讨论前可先看一页现状说明 [12-psychology-brief.md](12-psychology-brief.md)。具体怎么把一个人物写成文件见 [04-authoring.md](04-authoring.md)；两组之间已经对接的合同原文在 `data/sources/contracts/`；等对方交付的事项清单见 [plan/01-roadmap.md](../plan/01-roadmap.md) 的"阶段 C"。

## 1. 每类交付要说明什么

| 交付内容 | 必须说明 | 好的示例 |
|---|---|---|
| 主字段 | 构念、尺度、来源、是否测量 | “焦虑分面 1.2，角色设计值，非量表结果” |
| 自我理解 | 角色会如何解释自己 | “我只是需要弄清楚再答应” |
| 通常倾向 | 概率性而非永久绝对规则 | “高不确定任务中更可能索取证据” |
| 触发条件 | 可见线索与关系条件 | “重要合作方连续两次未兑现承诺” |
| 压力变化 | 能力/策略如何受负荷影响 | “先减少承诺范围，仍不凭空推断恶意” |
| 例外 | 何时应改变默认反应 | “出现可核对的兑现记录后恢复小范围合作” |
| 可观察信号 | 台词、动作、延迟、选择 | “请求回执、提出分阶段交付、拒绝不可控承诺” |
| 不应出现 | 可证伪的错误表现 | “未收到记录便宣告对方已兑现” |

未知数值保留缺失理由，不要写成 0 或中性值。模块级的缺失已能用 `unknown`（null）表达；分面级还不能，未来材料抽取模式需扩展分面级的 nullable 与缺失策略。

## 2. v1 文件怎么进入代码

心理学组的 v1 文件（`data/sources/psychology_v1/`：心理构念登记、角色状态说明、状态变化规则、三个心理流程 skill）就是交付本身。`python3.11 -m rolesim registry` 从中生成登记表 `data/registry.json`（87 个构念、75 个决策过程、11 个算子规则），每项带原文出处；原文改了而没重新生成时测试失败。代码只经登记表读取：

| 登记表里的内容 | 来自 | 用在哪里 |
|---|---|---|
| 构念的层（稳定 / 动态 / 记忆）、取值形式、实例键 | 构念登记、角色状态说明 | 状态布局（`slots.py`）、档案编译、输出 schema |
| 每个算子能写的构念、能在哪个阶段写、依赖组 | 状态变化规则、三个 skill 的 §4.2 | 状态存储的写入检查 |
| 各阶段可调用的决策过程及其可选项 | 三个 skill 的 §4.1、决策过程表 | 阶段提示与输出 schema；判断的过程和选项必须是登记的 |
| 快变 / 慢变、按事件等级的幅度档、效价 ×2、自我评价 ×4、证据封顶、人格移档 | 状态变化规则 §5.0 | 幅度检查（越界拒绝，不截断） |
| 衰减与恢复 | 状态变化规则 §九 | 只查方向；按经过时间计算要等场景时间单位（F3） |
| 自知程度、高影响字段 | 构念登记、角色状态说明 §8.3 | 自知层（不能自知的只以条件化语句进提示）；待审核清单 |

生成时发现的问题列在登记表的 `review` 里，等心理学组确认：没有任何阶段调用的决策过程（15 个）、未归入快变 / 慢变 / 类别的动态构念（21 个）、来源没写自知程度的构念（20 个，现在按不可自知处理）、可选项文字里夹有说明的过程（19 个）、§4.10 先验映射表里不在可选项中的候选（15 个）。

**决策过程现在怎么执行**：没有按规则实现的过程。每个阶段的模型调用在登记表允许本阶段调用的过程里做判断（过程 ID、选中的可选项、输出、证据），程序只检查过程和选项是否登记、证据是否可见。各过程的输出字段还没定（F2，见 [plan/09](../plan/09-interface-and-field-spec.md) 第 7 节），现在是自由对象。下面的模板是讨论一个过程时可用的格式，代码不读它：

```yaml
id: dm.social.trust_reputation_update   # 登记表里的过程 ID（决策机制库 3.4，S1 / S3 可调用）
psychological_hypothesis: 重复失约后更倾向先核查，兑现证据可支持有限恢复
trigger:
  observable_condition: 两次明确承诺均未在约定时间兑现
  insufficient_condition: 仅听到别人抱怨此人不可靠
options: [谨慎观察, 分阶段授权, 有条件修复, 彻底撤信]   # 取自登记表的可选项
output: {}                            # F2：这个过程的输出字段
exceptions:
  - 角色观察到不可控外部障碍
updates:
  - 可靠性判断改变，不能据此直接覆盖善意或能力判断
observable_anchors:
  - 请求具体兑现证据
counterexample:
  - 一次道歉就无依据地完全恢复信任
calibration: 待实验；不得把模板当已验证规律
```

## 3. 当前字段到底用于哪里

角色文件（persona 2.0）转换成档案时只带过来能一一对应到登记表构念的部分：P1 分面、依恋、施瓦兹价值、核心目标、表达基线、社会角色。其余要写进 `profiles/<id>.json`（profile-1，见 [04-authoring.md](04-authoring.md) 第 6 节）。

| 字段 | 当前用途 | 未实现部分 |
|---|---|---|
| P1 30 分面 | 稳定画像；按自知程度进入阶段提示（有条件化语句时用语句）；幅度档的人格敏感度（最多移一档） | 其余分面的行为投影；P2 / P3 的检查与映射 |
| 依恋两轴 | 稳定画像，按自知程度进提示 | 依恋特异触发、关系工作模型 |
| 施瓦兹价值、核心目标 | 稳定画像；核心目标的优先级基线作为入场的目标承诺；表达调用只看到核心目标 | 需要满足度、目标效用、价值冲突求解 |
| 情绪基线、自尊基线（profile-1） | 入场情绪的效价 / 唤醒、入场自我评价（角色状态说明 §8.2） | — |
| 71 维中的 1.1.4 / 1.5.2（profile-1） | 入场心理理论上限，标为待审核 | 其余条目的定义、评分、能力门 |
| 表达基线（`speech_style`） | 表达调用 | 更丰富的语言风格 |
| 发展位置、荣格功能、道德推理、文化取向 | `not_modeled` / `unknown`；不能自知，只以条件化语句进提示 | 全部待审定与实现 |
| `mechanism_priors` | 现行管线不读（旧机制卡已删除） | §4.10 决策偏好先验映射未做 |

## 4. 第一批共同审定材料

建议每位人物准备三个短场景：低压力基准、同内容高压力、出现纠正证据后的恢复。另做信息可见/不可见对照。每个场景允许多个可接受行动，并要求说明“什么条件下属于合理变化”。

首批需要补齐：第一版启用哪些模块与决策过程（F5）；启用的过程各自的输出字段、强 / 弱触发和例外（F2）；登记表 `review` 清单的确认；原引用的 71 维定义文件；两到三个真正希望研究的角色材料（写成 profile-1，带条件化语句）。服务器地址与模型选择是后续配置，不影响本地结构审定。

## 5. 两组之间的协作流程

心理学组回复确定的流程：**登记 → 评审 → 投影 → 校验 → 发布 → 回放**。

1. 心理学组登记或修订构念。
2. 双方评审边界与可实现性。
3. 工程侧生成状态说明与规则表的机器投影。
4. 自动检查引用、范围、版本。
5. 用小剧本回放。
6. 发布带四类版本号的合同快照。

三份材料只允许一个语义主来源；合同只做追溯入口，不复制正文。字段删除或改名属于不兼容变化，需升版本。
