# 设计演变

本文记录框架从 v0 到现在经历的几次重构，每一版为什么改、改了什么。现在的设计见 [14-interfaces.md](14-interfaces.md)；每次改动当时的验证结果见 [15-verification-log.md](15-verification-log.md)。旧版的计划文件（原 plan/01、02、07、08、10）已删除，原文可在 Git 历史里查到。

## 1. 三个版本对比

| | 原 v1（2026-10） | 重构初版（2026-11-07—09） | 现在（C8，2026-11-09 起） |
|---|---|---|---|
| 代码形态 | 一个 `Agent` 类加函数，内部全是 dict | 接口化（Protocol），接入心理学登记表 | 接口不变，`rolesim/` 按 4 个顶层接口分子目录 |
| 模型输出 | 0—1 的线索值（压力、不确定等）和一个动作 | 判断，**再加上状态提议**：模型自己挑构念、字段和数值 | 只输出判断；数值只在程序给的区间内选 |
| 谁决定状态 | 程序：机制卡加手写公式（`tension_v1`、`trust_v1`） | 实际上是模型，程序只能事后校验 | 程序：算子按规则卡生成槽位，`IMagnitude` 先定区间 |
| 心理学材料 | 没用上，卡片参数是"未校准的工程假设" | 整份登记表塞进 prompt，交给模型自己读 | 登记表由程序执行，模型只看到要它判断的那部分 |
| 人格怎么起作用 | 写在 prompt 里，靠模型体会 | 同左 | 在 `IMagnitude` 中移动区间，模型拿到区间时人格已经起过作用 |
| 原值未知 | 默认值兜底 | 容易被当成 0 | 给首次取值范围，有方向的字段只放在判断的那一侧 |
| prompt 中的 schema | 很小 | 67—117k 字符，8B 模型频繁出格式错误 | 完整版 11—15k 字符，提示里约 2—3k，结构化解码强制遵守 |

原 v1 能直接跑，是因为模型的负担很轻：只给几个线索值和一个动作。但它的状态规则只有两条手写公式，用不上心理学组的材料。重构初版接入了登记表，却把状态变化也交给了模型：harness 的作用体现不出来，模型的压力太大。C8 保留了初版的接口化和登记表，把状态控制权收回到程序。

## 2. 时间线

### 2.1 v0 合同与 state-v1（2026-10-15—19）

- 和心理学组、环境组对接了接口合同 v0（`data/sources/contracts/`）：`step` / `perceive`、五块动态状态、7 个机制名。
- 心理学组回复后升级到 `state-v1`：六个状态域、六种模块状态、11 个更新算子的写权限、依赖组原子提交、三级错误（硬错 / 软错 / 豁免）、`mechanism_log`、四类版本号。
- 人物档案升到 persona schema 2.0（施瓦兹 19 项价值、1—3 个核心目标、`module_status` 覆盖 20 个模块）。
- 三档消融入口、盲化评审包、自动审计。

这些结构里的"原子提交、三级错误、可见性校验、四类版本号、接口适配层"沿用到了现在；六域状态和路径式白名单在重构中被按构念 ID 的状态取代。

### 2.2 人格线、社会情境线与多 agent（2026-10-20）

- 角色文件（档案 + 人格 skill + 开场设定）与剧情文件分开，一个角色一个文件、一个剧情一个文件。
- 开场设定 `goal / disclose / conceal / recap`；隐瞒只允许"不提"和"说得模糊"。
- 9 个人格 skill（兼容 Agent Skills 规范），按线索和开场设定激活；路线选 context engineering 为主（[10-persona-skills-survey.md](10-persona-skills-survey.md)）。
- 去掉事件脚本，改为 2—6 个角色基于共享背景自主对话；scene 3.0；规则驱动的环境 agent。
- 机制卡 2.0（触发条件 / 改哪个状态 / 怎么改），状态三档进入评价、决策、表达。这一版的机制卡和三档状态在 2026-11-08 随旧管线删除。
- 第一次接本地 Qwen3-8B 跑通 5 轮，表达层台词复读（这个问题现在还在）。

### 2.3 接口 v1 与 v2（2026-10-21、11-07）

- 10-21：环境组提出新的 Agent 接口（`act` / `perceive` / 环境 `act`，认知五字段），实现了角色适配器和本地交互循环。
- 11-07：环境组发来接口说明（本仓库称接口 v2）：只有 `initialize` / `act`，没有 perceive，不回传认知。外部接口层改为 v2；同日与环境组确认：角色 ID 即角色库 ID、在场者含本人、不行动的角色不更新、亲见 / 转述由文字表达。

### 2.4 按心理学组 v1 材料重建（2026-11-07—08）

心理学组交付了 v1 接口文件（构念登记、角色状态说明、状态变化规则、三个心理流程 skill）。原来的结构与它差距很大：路径式命名而不是构念 ID、动态状态只有"紧张"和"信任"两条规则、5 张机制卡对 75 个决策过程、缺"长期演化"阶段。于是按"对象—字段—接口"重新设计，定下设计约束 C1—C8（[01-design.md](01-design.md) 第 2 节）和 4 个顶层接口，分 7 步重建：

1. `IRegistry`：从 v1 文件生成登记表，每项带原文出处。
2. `IStateStore` + 算子 + `IValidator` + `IMagnitude`：按构念 ID 的状态，权限和区间来自登记表。
3. 通用 `IModel` 与三个阶段的输出 schema。
4. `IEvidenceGate`、三个 `IStage`、`IExpresser`。
5. `ITurnRunner` 替换 `Agent.step`，`ITrace` 自己落盘。
6. `IRoleRepository` / `IProfileCompiler`：档案编译与入场状态。
7. 删除旧路径（`agent.py`、`state.py`、`stateview.py`、`mechanisms.py`、`contract.py`、`runtime.py`、`modules.py` 等），开场设定、人格 skill、消融模式和离线工具移到新管线。

这一版里阶段调用除了判断还产出**状态提议**（构念、键、字段、目标值、事件等级），算子只是整理这些提议，区间在选值之后才算、只用来检查。

### 2.5 接真实模型与结构化解码（2026-11-09）

用 vLLM 0.17.1 + Qwen3-8B 跑，先是格式错误（证据写成文字、数值写成字符串），接上结构化解码后变成语义错误：键里写占位词、改写目标的固定字段、幅度超档。S2 计划的依赖组连续被拒，没有一场能跑完。这说明问题不在格式，而在分工：模型被要求管状态。

同日按接口把 `rolesim/` 分成 `agent/`、`role/`、`stage/`、`state/`、`run/`、`offline/` 六个子目录。

### 2.6 按 C8 改回"模型判断、harness 管状态"（2026-11-09—10）

依据状态变化规则v1 §5.0（程序规定合法范围、事件等级和硬上限；模型只能在规则卡允许的区间内选择具体变化并给出理由）、§二（决策过程只产中间判断，没有写权限）和事件建模skill §3.9（候选状态变化由相应更新算子生成）：

- 去掉 `ChangeProposal`；阶段只返回产物和判断，6 个有机制卡的过程带类型化输出。
- 新增 `ChangeSlot`、`Skipped`、`IStateStore.draft`、`IValueChooser`；`IUpdateOperator.propose` 改为读判断和产物；7 个算子按规则卡生成槽位，区间在选值之前算好。
- 删除只为"模型写状态"服务的部分：按地址的提议分支、键改成列表、`unjudged_mechanism`、提示里的构念字段表与幅度参考表。

结果：Qwen3-8B 第一次跑完整场 test1（8 轮、48 次调用、没有被拒绝的变化、审计通过）；人物差异由 `IMagnitude` 按人格移档产生。暴露的问题列在 [plan/01](../plan/01-engineering-backlog.md)。

## 3. 一直没变的约束

- 稳定画像在一场互动里只读；长期变化只能以修订候选提出，经审核后出新快照（这部分还没实现）。
- 状态只由本角色可见的证据更新，每条变化引用记录编号。
- 越界拒绝，不截断。
- 世界私有数据和他人的隐藏心理永不进入角色的任何调用。
- unknown 与 0 / 中性值不同。
- mock 输出和工程测试通过都不是心理有效性证据。
