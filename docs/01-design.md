# 从两份心理机制库到角色模拟

## 1. 我们要构建什么

目标是一个**由心理学构念约束、能够在具体情境中行动并跨轮更新状态的虚构角色系统**。心理学同学提供构念边界和条件性行为假说，工程系统负责使这些假说进入可观察、可复核的运行流程。

两份库非常适合成为设计底稿，但概念整理与经过验证的心理模型不同。原文中的“高”“低”“阈值”“权重”还需要操作定义。首版不应自动把每个理论转成独立随机数字，更不应把人物的年龄、性别、职业直接映射成心理优劣。

## 2. 五类对象分别保存

| 对象 | 回答什么 | 示例 | 生命周期 |
|---|---|---|---|
| 稳定画像 | 通常如何反应、重视什么、能做什么 | 人格分面、需要、价值、能力 | 普通轨迹固定 |
| 自我理解 | 角色知道或愿意承认自己什么 | “我只是希望事情可靠” | 首版人工填写 |
| 初始情境 | 处于什么位置、知道什么、能采取什么行动 | 交付义务、已收到的记录、权限 | 每场景初始化 |
| 动态状态 | 此时被怎样影响 | 紧张、当前目标、信念、关系判断 | 事件后有依据地更新 |
| 机制（决策过程） | 在什么条件下怎样处理输入与选项 | 评价、信念更新、冲突模式 | 每个阶段在登记表允许的过程里判断 |

能力、倾向、策略和状态不合并成“角色心理分数”。“能识别对方意图”不等于“愿意替对方着想”；“重视合作”不等于“每次让步”；“这次紧张”不意味着人格神经质被提高。

## 3. 画像构建流程

1. **选定使用任务和角色来源。** 先限定合作冲突、承诺修复等情境；指定是虚构设计、材料抽取还是人工标注。三者的来源必须分开。
2. **定义人物的现实约束。** 职责、关系位置、资源、长期目标、已经知道的事实。可见信息由场景包给出，不塞进无差别的角色简介。
3. **选择一个主人格方案。** 首版 P1。P2/P3 保留为后续替代方案；不把大五、HEXACO、16PF 重叠维度叠加。
4. **填写少量有任务意义的字段。** 完整结构可保留，未使用字段明确中性/未知/关闭，并记录原因。中性赋值与没有资料不是同一含义。
5. **审查张力。** 高焦虑但善于合作、高推断能力但低关怀等组合可以保留，只要有条件性解释。不要把所有好属性捆绑。
6. **按自知性分层进入提示。** 稳定画像保存理论字段和来源；角色能自知的模块才以内容进入它自己的提示，不能自知的只以条件化语句出现；别人只能从可观察的行为里推断。
7. **生成条件化行为描述。** “一般倾向—触发条件—压力变化—例外—可观察表现”，避免永久绝对化。
8. **心理学审定。** 检查字段含义和行为锚点，再进入模型实验。

当前代码完成手工 JSON 档案的校验与编译：档案里每项标明来源类型（明写、按规则推断、模型推断、默认、未知），模型推断必须带逐字引文并进入待审核清单；没有实现“从任意材料自动估计全套心理参数”。

## 4. 心理过程如何进入运行

机制库目录与可执行定义分开。目录保持原文内容；心理学组的 v1 文件（构念登记、角色状态说明、状态变化规则、三个心理流程 skill）经脚本生成登记表 `data/registry.json`，代码只经登记表读取构念、决策过程和算子规则，每项带原文出处，原文改了而没重新生成时测试失败。

一次行动按心理流程 skill 分成三个阶段：**S1 事件建模**（这件事是什么、对我意味着什么、有哪些可能的解释）、**S2 行动计划**（候选、选择、承诺、怎么表达）、**S3 长期演化**（对上次计划的回应与预期相比如何、承诺、关系走向、带到以后的东西）。每个阶段是一次结构化模型调用：模型在登记表允许本阶段调用的决策过程里做判断，并提议状态变化；程序不替模型做心理判断，只检查判断和提议是否落在登记表的范围内。

状态只经 11 个算子写入，每个算子能写哪些构念、在哪个阶段写、属于哪个依赖组都来自登记表；一次变化的幅度按事件等级分档（状态变化规则 §5.0），只有听说或推断的证据时封顶，人格敏感度最多移一档。这些区间是心理学组给出的初始值，不是实证规律，未经校准；没有调研依据的人群相关系数与标准化常模不能凭空添加。

现在没有按规则实现的决策过程：过程的判断全在模型调用里，各过程的输出字段等心理学组确定（见 [plan/README.md](../plan/README.md) 的待定项）。消融模式 `profile_state_mechanisms` 才让模型做决策过程判断，另两种模式用来对照。线索（压力、不确定、承诺、修复、冲突）由 S1 站在角色立场给出，只用来激活人格 skill；没有宣称线索判断的准确率。

## 5. 每一轮的设计原则

具体的函数调用链和参数传递见 [06-runtime-flow.md](06-runtime-flow.md)，这里只记设计上的几条原则：

1. 环境只投递角色有权限观察的事件。
2. 状态更新器处理每个事件一次，并保留事件 ID；他人的口头提议不能作为已经兑现的证据。
3. 每个阶段给出结构化产物、决策过程判断和状态变化提议，引用可见记录的编号作为证据。记录的是审计摘要，不要求逐步思维链。
4. 状态存储拒绝不可见或未知的证据引用、越权或越界的变化及任何写稳定画像的提议；阶段输出不合 schema 或登记表时整个阶段失败。
5. 表达模型只获得表达所需的信息，产生思考、台词和动作；不替它说出机制、分数和隐瞒的内容。
6. 环境裁决实际发生了什么。提出计划只是提出计划；接受、成功、资源转移须由环境确认。
7. 角色依据可见反馈更新，保存状态与轨迹，进入下一轮。

当前环境是 2–6 个角色基于共享背景按座位轮流自主行动，角色放在环境组接口 v2 后面，本地参考运行器只开场、按接收者分发、到轮数收尾，不写剧本；可选一个规则驱动的环境 agent 改变时间、天气等世界状态（见 [plan/02](../plan/02-multi-agent-and-state-mechanism.md)）。尚没有动态发言顺序、群体状态规则、非对话行动和世界事实。

## 6. 信息边界的落实

- 环境真值不等于角色知识。任何阶段和表达调用都不接收 `world_private`。
- 角色自己的完整心理字段也不全等于其自知。不能自知的倾向只以条件化语句进入提示（“说不出来、但会影响你的倾向”）；不让角色直接背诵量表标签。
- 他人画像只通过可观察行为进入。对别人的推断是带证据的他人模型，不能复制对方的稳定画像或状态；别人的思考和开场设定永远不进入自己的提示。
- 当前记忆是只增的条目（`m.entry`），每条带来源事件与通道；阶段开始时按字面相似度、重要性和可及性取回。信念带置信度和冲突组，但还没有完整的矛盾消解和误信修订。
- 权限过滤可以检查输入隔离，不能单凭这一点保证自由文本没有幻觉。台词与行动意图一致、事实依据充分、隐私披露合理仍需要语义审查与实验评测。

## 7. 当前模型参数的证据边界

P1 的 `[-2,2]` 是原库内部编码，不是原量表分数。示例参数均为合成人物设计，`confidence: 0` 表示未经测量验证。情绪敏感度与恢复参数在示例中由焦虑/脆弱性分面作工程投影，避免把同一构念再独立抽样；公式本身未校准。需要与价值的 `[0,1]` 是首版局部相对权重，不能跨人物解释为常模百分位。

71 维定义缺失时，不使用虚构维度或全零向量冒充“已经启用能力模型”。完整定义与任务锚点接入后，才讨论中性默认、能力上限和压力衰减。

## 8. 推进顺序在哪里

推进顺序、各阶段完成情况和下一步计划不在设计文档里维护，见 [plan/README.md](../plan/README.md)。设计上有一条始终成立的原则：每新增一个机制或字段，都要有对照情境和独立验证，不先铺成一张任意赋值的大表。
